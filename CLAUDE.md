# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

HeroQuest-based tabletop RPG with an AI game master ("MJ IA"). Self-hosted, internal project (LAN play between friends — no public deployment). Implemented so far: deterministic engine (`app/Engine`, Pest-tested), full DB layer (migrations/models/seeders per `reference/12_schema_donnees.md`), AI GM module (`app/Agent`: Anthropic client, per-task skills with JSON schemas, Qdrant bible client, queue jobs, Reverb events), game-loop services (`app/Partie`), REST API, and the Vue front ported from the `reference/heroquest/` mockups. The API/front/realtime contract lives in `docs/contrat-api.md` — change it there first. The whole MVP scope of `reference/00_synthese.md` §8 is covered (combat, checks, traps, spells, market, votes, levels, Dread/bosses, campaign closure, snapshots/reprise).

**Consolidated rule: every durable game state lives in the DB, never in cache.** The cache holds only ephemera — the current menu, the market phase, narrator presence. Exploration progress, searched rooms and the search deck all started life as cache keys with a TTL; losing one re-closed the fog over explored ground and **froze the whole group** (playtest verdict §2.16). Never reintroduce that pattern: add a column.

**Searching & artefacts.** "Fouiller — trésor" draws a **search card** from a per-quest deck (`quetes.deck_fouille`, built at quest start from `gabarits_quete.structure.deck_fouille`, drawn **without replacement**). The composition mirrors the **board game's treasure deck**: 2 gems (35 gp), 2×25, 2×15, 2 jewels (50 gp), 2 pit traps, 2 arrow traps, 3 healing potions, one each of heroism/strength/defence, and **6 wandering monsters** — the commonest card by far, and they have **no cap**: since every card returns under the deck, a budget would have turned the deck's most frequent card into a blank. Each quest always summons the *same* creature (cheapest base-tier), the board's "quest wandering monster". Issues: `tresor` · `potion` · `artefact` · `errant` · `piege` · `rien`. Cards go **back under the deck** after being drawn, so it cycles instead of running out — with one search per hero per room, a 6-room dungeon at 4 players yields up to 24 draws, exactly the deck size. **One search per hero per room** (`Quete::aFouille()`, entries stored as `"{salle}:{personnage}"`): the first searcher no longer closes the room for everyone, each hero draws their own card as on the board. Loot goes to the **searcher** — gold to the common purse. Two healing items on purpose: the **Fiole de soin** found in the deck heals **1d6** (`soin_pv_body_de`, `unique` so it never reaches a stall), while the **Potion de soin** bought at market heals a fixed amount. A trap card **ends the turn** (`a_joue`), and the **Potion d'héroïsme** grants a *second attack* this turn (`etat.attaque_supplementaire`, same pattern as the magicien's Réserve arcanique) — not extra dice, since attack comes from the weapon here. Each card is self-contained (`{issue, or?, objet_id?}`), so drawing consumes **no die**. The deck is **reshuffled at every build AND at every snapshot restore** (`random_int` seed — never derived from the group, René's call 2026-08-05): it used to be seeded on `crc32("{identifiant}:{positionArc}:fouille")`, so a "Recommencer la quête" or a post-TPK reprise replayed the *same draw in the same order* and handed the group an ordered list of its own treasures, traps and wandering monsters. Restoring keeps the **composition** (the deck cycles, no card is ever lost) and re-rolls the **order**; `salle_artefact` / `salles_coffre` / `artefact_objet_id` stay pinned — those are map-bound *placements*, not draws, and re-rolling them would move the chest under the party's feet or grant a second unique weapon. Separately, one designated room — the **deepest** in the corridor tree (`quetes.salle_artefact`) — holds **at most one** `unique` weapon (`quetes.artefact_objet_id`); it consumes no card, and the hero who searches it gets the item. No unique weapon left (uniqueness is **per group**) → the chest pays `or_coffre` instead. Artefacts are **never** purchasable, sellable or forgeable. A full bag does **not** block the reward: the item is handed over in overflow with `sac_deborde: true` (refusing it would lose it forever), and `/moi` exposes `equipement.capacite`/`occupation` so the controller can show it.

**Map generation.** `app/Partie/AssembleurCarte.php` lays rooms on a 2D branchy tree of uniform slots. A **threshold is ONE cell** — the board only has single-square doorways (René's call, 2026-08-08). Thresholds used to be 2 cells wide so a tank couldn't block the shooter's line of sight (playtest 2026-07-31, a magicien mute for 8 turns); but the official game solves that case **differently**, with the **diagonal attack** — "two heroes at once may attack a monster blocking a doorway" (LR p. 14, `reference/16_armurerie.md` §6.2), a rule the engine already applies (`attaque_diagonale`). A corridor therefore carries **2 doors, one per room**, sharing a `jonction` id; `MoteurPortes::ouvrir()` opens only the **threshold pushed**, never the far end — grouping the whole junction meant the party reached the end of a corridor to find the door already open, on a room still unrevealed. The corridor itself keeps its second lane: it widens the **corridor**, never the threshold. The room pool must stay **varied** (≥ 6 distinct shapes): it had shrunk to 3 shapes each duplicated, because `TuileSeeder` used `create()` and was re-seeded — every room in a dungeon looked identical and players lost track of where they were. It now purges before seeding. Rooms are placed **compactly** (`candidatLePlusCompact()`: most adjacent placed rooms first, then closest to the centroid) rather than at random. A randomly-spread tree almost never folds back on itself, so it offers no pair of adjacent-but-unconnected rooms — and without one, **no loop and no secret door are possible at all**. Combined with a floor of **5 rooms** in every gabarit (a 3-room polyomino has exactly 2 adjacencies, so a cycle is geometrically impossible; 4 rooms only manage it 59 % of the time), this guarantees **at least one secret door per quest** — locked by `CouloirsTest`.

Beyond the spanning tree, `liaisonsSupplementaires()` adds **extra edges between grid-adjacent unconnected rooms** — loops, roughly one per two rooms, every other one `secrete`. Two reasons: a pure tree has a single route between any two rooms, and secret doors had **nothing to open** (so "Fouiller la zone" only ever found traps). Hard invariant, tested: a room is **never** reachable only through a secret door — a failed search must never strand the group. Room counts are drawn uniformly across the gabarit's `salles.min..max` (widened to 5-value spreads so quest size actually varies).

`accolerSallesMitoyennes()` slides some **leaf** rooms flush against their parent so the two share a wall: the existing carver then produces a length-1 corridor — i.e. a plain threshold, a door straight from one room into the next (~1 per dungeon). **Leaves only**: shifting a room along its edge axis moves its perpendicular median, and every corridor is straight only because medians align — a leaf has just one edge, so nothing breaks. The shift is abandoned if it would overlap another room.

**Traps sit in rooms as well as corridors**, never in the **start room** (a trap under the party at turn 1 is suffered, not played) — candidates are shuffled as one pool, since keeping corridor midpoints first put 58 of 61 traps in corridors and left every room perfectly safe. Only heroes trigger them: `MoteurPieges::declencher()` takes a `Personnage`, so a monster cannot be passed — a creature standing on a trap is an ambush, not a bug.

Doors are drawn once, in the shared `resources/js/components/carte/DungeonGrid.vue` (both the table map and the controller's movement sheet). Every door renders its two **jambs** — an open door used to be a 2px dashed line at 50% opacity, invisible on the controller's 22px cells, and a playtester twice mistook an ally's cell for a threshold. The leaf now only conveys state: gold closed, absent when open, violet for a revealed secret door. All these properties are locked by `CouloirsTest`.

**Throwing a weapon.** A main-hand weapon flagged `jetable` (Dague, Hachette) can be hurled at a monster in clear line of sight: `MenuMoteur` emits a distinct `lancer` option, `ResolveurTour::resoudreAttaque()` treats it as ranged for that one blow, then `consommerArmeLancee()` **deletes** it — a thrown weapon is lost, dagger included, it stays where it falls. Combat dice are recalculated, so a hero who throws their only weapon immediately sees themselves back to bare hands. The action slot is the only rate limit. Until now `jetable` was a **decorative key with no reader** — the dagger had advertised a throw the engine never performed.

**Room furniture blocks — on two independent axes.** The grid knew only `m` (wall) and `s` (floor); the board is furnished, and those pieces bar the way as much as they dress the room. `mobiliers` is a seeded catalogue (8 types — the only ones whose footprint could be **measured** on the official quest maps, since no booklet ever states one; the 3 unmeasurable ones are deliberately left out), and `AssembleurCarte` lays a third `carte.mobilier` layer on the exact pattern of `leviers`/`pieges` — no new cell type, no tile migration. `FabriqueGrille::pour()` holds the **single** furniture loop in the whole engine; a second path would let movement, targeting and line of sight drift apart. Footprints reuse `cellulesEmprise()`, already written for large figures.

Movement-blocking and sight-blocking are **separate flags** (`bloque_mouvement`, `bloque_vue`): you see over a table, not through a bookcase. A **third** joined them on 2026-08-21, `adosse_au_mur`: placement drew a random floor cell and flipped a coin for orientation, never looking at walls — measured over twelve real dungeons, a bookcase followed the wall **four times in ten** and a cupboard **one in six**, the rest jutting perpendicular into the room like a shelf divider, or floating outright. A declared-mural piece now requires a wall **along its long axis** (a wall at the *end* of a bookcase pins it, it doesn't back it) and is otherwise **not placed at all** — same refusal as the connectivity check. ⚠ **Never derive this from `bloque_vue`.** The three tall pieces happen to be the three that belong against a wall, and "tall, so it occludes *and* leans" is tempting — but a **pillar** blocks line of sight and stands in the *middle* of a room (René, before it bit). Deriving it would either glue the pillar to a wall or, worse, refuse to place it where it makes sense. Exactly why `bloque_mouvement` and `bloque_vue` were split in the first place: independent facts don't share a column. Splitting the column was not enough — furniture used to land in the same `$occupees` set that `figuresBloquent` tests, so a table went on stopping arrows by that other route. `Grille` therefore keeps **three** sets: `$occupees` (figures only — heroes, monsters, allies, the only one `figuresBloquent` consults), `$obstacles`, `$opaques`. Furniture is scenery, not a figure: it occludes like a wall, unconditionally. The split by **height** (bookcase/weapons rack/cupboard occlude; table/chest/throne/bench/tomb don't) and the blocking itself are **porting decisions**, not readings — no booklet addresses either (`reference/17_mobilier.md`).

The hard invariant is connectivity: a badly placed piece cuts access to a chest or a lever and freezes the group. Placement re-checks reachability from a **single** threshold and abandons the piece otherwise (a multi-source BFS misses pockets — every threshold counts as reached merely by being its own source, so a piece sealing one into a 2-cell pocket passes). It rejects ~2.4 placements per dungeon; never in corridors, never in room 0, never on a trap (which would be both invisible and untriggerable). **Each searchable piece has ITS OWN loot table, and is searched once PER HERO** (`mobiliers.effet.fouille`, René's call 2026-08-17 — it overturned both halves of the previous rule). A piece used to draw a card from the *quest's* search deck, once for the whole group: a weapons rack could hand out a healing potion, it burned a card the room searches would have drawn, and the first hero to arrive closed the piece for everyone. Now the chest pays often and can yield a weapon, the throne gives gold only, the alchemist's bench only flasks, the **bookcase is the only piece that yields SCROLLS** (which makes it the caster's furniture), the weapons rack yields weapons and armour. ⚠ **Every table carries a `rien` outcome**, and a test demands it — a piece that always gave something would turn exploration into harvesting and stop gold being a resource. Two pieces **bite**: the tomb (`Aiguille empoisonnée`, 1 Body or poison) and the alchemist's bench (`Fiole de poison` — the catalogue's only trap with no `aleatoire` branch: it poisons outright, which is *harsher*, 3 turns at 1 Body, though resistible where a flat hit never is). Draws are **weighted**, which is what lets a chest pay often and a throne disappoint half the time; and when the issue is `objet` the piece is picked in **two steps** (`App\Engine\RareteButin`, René's call 2026-08-17) — the **rarity** first, weighted by the group's **average level** (commun/peu_commun/rare going 70/28/2 at level 1 to 20/45/35 at level 7+), then the piece uniformly inside it. It used to be uniform over the whole pool: a bench handed out an 800 gp potion as often as a 100 gp one, and a level-8 party kept finding daggers. ⚠ There is **no level cap** (doc 01 §5), so the curve **saturates** at the last band; and only rarities actually **present** in the pool are weighted — a rack with no rare weapon yields what it has rather than nothing. ⚠ The pool also **drops anything nobody present could use** (René's call 2026-08-17): three potions are barbarian-only and two elf-only, so a party without a barbarian spent the campaign finding Battle Rage — loot that is neither playable nor sellable mid-quest, and that eats a bag slot. The filter crosses `tag_equipement` with the masteries of the heroes **engaged in the quest** (`Equipement::tagsAccessiblesAux()`), the same rule the class artefacts already used and now sharing its home with them; an empty list means **no restriction** (fail open). ⚠ Rarity itself is now **derived from price** (≤150 commun · ≤400 peu_commun · above rare) instead of hand-set per row, where it had drifted (a 200 gp hatchet "commun" while a 125 gp wand was "peu_commun"); only artefacts (`unique` is a status, not a price band) and scrolls (rarity = spell difficulty) keep a declared value. issues reuse the deck's vocabulary (`tresor`/`objet`/`piege`/`rien`) so `appliquerButin()` applies them without knowing their origin. ⚠ The **Explorer's Sixth Sense is rewired onto this path**: its card says "when you draw a trap card, put it back and draw another" — it speaks of the *gesture*, not the deck, and leaving it out would have silently nerfed it exactly when furniture became dangerous; on a weighted table, re-drawing is re-rolling. ⚠ `fouille_par` stacks hero ids like `quetes.tresors_fouilles` does for rooms; the legacy boolean `fouille` is still read and still means "spent for everyone", so a quest already in flight keeps its pieces closed rather than refunding a search already used. ⚠ `MobilierSeeder` **keys on `nom` and no longer purges**: `cartes.grille.mobilier[]` stores a `mobilier_id`, so re-seeding mid-campaign used to orphan every piece of an in-flight quest — neither searchable nor blocking, without a single error. And a furniture search publishes **no `deck_restant`**: it never touched the deck.

**One silhouette per family on the map, and a legend behind an info button** (René, 2026-08-27). The board carries six families of marker, and they share a room: figures are **round**, traps **square**, épreuves a gold **lozenge**, levers a blue **octagon**, furniture a filled block over its footprint. The épreuve marker first shipped as a 72 % gold disc — the exact silhouette of a hero token, and on the table it read as a fourth figurine standing between two heroes. ⚠ **The `leviers` layer was published NOWHERE**, so no lever was ever drawn on either map. That cost nothing while none were ever placed; it costs a locked dungeon now that forcing one takes a Body roll and a room may hang on that door alone — the option only appears on contact, and nothing said where to go looking. Levers carry no room index (`{x, y, levier_id}`, the original format), so the fog filter **derives** it from the coordinates; a **corridor** lever is always shown, since a corridor has no room index and is never "discovered". Its published `difficulte` goes through `DifficulteBody::plafonnee()` exactly as `MenuMoteur` does — publishing the raw value would print "difficulty 3" on a map whose menu offers 2. ⚠ **Illustrations go in the legend, never on the map**: at 22 px on the controller a picture turns to mush, and it would erase the silhouette, which is what the player reads at a glance — the shape says the *family*, the image says the *content*. Traps and épreuves had published an `image_url` all along and it was displayed **nowhere**; **furniture had none at all** — no prompt template, no generation, no field — though a piece is searched and smashed exactly as a trap is disarmed. `config/images.php` gains the `mobilier` template, `BibliothequeImages::urlMobilier()` the accessor, `images:generer --type=mobiliers` the iteration, `EtatGroupe.carte.mobilier[]` the field, and `PlaceholderController` its emblem (a top slab on two legs — a chest or a throne would have named ONE piece where the emblem stands in for all eight). **Levers and doors are illustrated too** (2026-08-29): they are the only two room elements with **no catalogue table** — a lever is just an id in the grid, a door an edge — so they are named like the **classes**, by a fixed label (`catalogue/leviers/levier.png`, `catalogue/portes/{etat}.png`) rather than `{id}-{slug}`; there is no row to number. ⚠ **One image per door STATE** (closed, open, locked, secret): the state is what carries the information, and a single picture would make a barred door and a hidden passage indistinguishable. `config('images.portes')` is keyed on `MoteurPortes::ETAT_*` and confronted with it **both ways** by a test — a state added to the engine with no illustration would fall silently back to the SVG emblem, and an orphan entry would generate a picture nothing ever fetches. Icons live in `resources/js/components/carte/symboles.js`, read by **both** the renderer (`DungeonGrid`) and the legend (`LegendeCarte`): a legend kept apart from the rendering goes stale at the first symbol added, and then it lies with a legend's authority. `SymbolesCarteTest` confronts that table with the catalogue **both ways** for traps, épreuves and furniture, and checks that both components import the one file. The legend lists only what is **on this map** — a legend describing seven traps for a room holding one reads as documentation, and stops being opened.

**The controller's map is zoomed, and panned by a D-pad** (René, 2026-08-28). Cells were **22 px** — below any touch-target guideline, so players hit the neighbour, and the markers on them shrank to a smudge. They are **38 px** now, which no longer fits the screen: the four arrows plus a **recentre-on-my-hero** button in their middle are the *counterpart* of the zoom, not a separate feature. The finger is for **choosing a cell**; making it also drag the map makes both gestures ambiguous, since a short drag reads as a tap and sends the hero somewhere unwanted — native scrolling still works, the pad only makes it explicit. The pad hides itself when nothing can scroll, and each arrow greys out at its own edge (a dead button reads as a frozen map). ⚠ **Marker glyphs did not follow the cell**: `62 %`/`64 %` resolve against the *inherited font-size* (~16 px, so ~10 px whatever the cell), furniture was pinned at 14 px, and traps sized on `1.3vw` — the *screen's* width. Nothing showed while the map was 22 px; the first zoom would have given big cells with tiny symbols. `--dg-cell`'s companion `--dg-icone` is now set by the parent alongside the cell size, defaulting to the old values for the table (whose cells are `1fr` and cannot state pixels). ⚠ And wrapping the scroller to host the pad **exposed a latent overflow**: `.dep-ov`'s grid track sized itself on the sheet's content, so the sheet reached its 520 px `max-width` on a 412 px screen — measured — putting the header's close cross and half the pad off-screen. `overflow: auto` had masked it as long as the scroller was the sheet's *direct* child (a scroll container has zero minimum size, a plain `div` does not); `grid-template-columns: minmax(0, 1fr)` fixes it at the root. It is the §2.2 defect returning through another door.

**The table shows what is IN the active hero's room** (René, 2026-08-29). A second button beside the legend: the legend explains the **symbols**, the preview enumerates the **contents** — figures (a dressed monster carries its catalogue `nom_base` underneath, since "Le Noyé de Gorrim" does not say *goblin*), furniture, épreuves, known traps, levers and exits, each with its illustration. It follows the turn order by itself. ⚠ It **remembers** the last active hero: during the monster phase no hero has the hand, and the panel would blink out at every turn's end — exactly when the table is watching what happens in the room. `EtatGroupe.carte` gains `salles: [{index, x, y, largeur, hauteur}]`, ⚠ **discovered rooms only** — `cases` is already fogged, and publishing every rectangle would hand over the number, size and position of rooms never opened, the fog walked round by the back door. ⚠ `App\Partie\Salles::indexDe()` is now the single point of passage for "which room holds this cell?": the question was asked in **six** places, each with its own loop (two in `ResolveurTour`, one in `DemarreurQuete`, one in `AssembleurCarte`, the fog closure and the lever filter in `EtatGroupe`). They all said the same thing, which is precisely the risk — the rule is too simple for anyone to notice one copy drifting, and a single `<=` for `<` moves a border cell to another room depending on who is asking.

**One action, then a sub-choice** (René, 2026-09-01). The menu no longer carries **one option per spell** — it carries **one option that carries the list of spells**. Measured in real play, a level-1 wizard's menu held **14 options, 9 of them spells**, where the design doc sets "2 to 5 clear options" (doc 13 §3.1). It is the targeting lesson one level up: *the option must not BE the spell, it must CARRY the list of spells.* Three options now: `lancer_sort` (`parametres.sorts[]`), `lire_parchemin` (`parametres.parchemins[]` — a separate action, because a scroll is **destroyed** and demands a Mind roll from a non-caster, two economies that don't belong in one list), and `utiliser_objet` (`parametres.objets[]`, potions and material together). The client answers flat: `{cle, cible_id?, cible_type?}`. ⚠ **The list IS the whitelist** — `entreeChoisie()` checks membership and 422s otherwise; without it a client would cast a spell from their repertoire **with another spell's targets**, out of line of sight and outside the target typing `ciblesLegales()` computed for that one. ⚠ **`cibles` stays PER ENTRY**: a damage spell sees monsters and heroes, a heal only heroes, a self-spell nobody — one list at option level would be wrong for five of a wizard's nine spells. ⚠ **Depth follows the data**: the third level opens only when the chosen entry carries `cibles`, so a self-only spell (*Métamorphose*, *Ailes sombres*) and a healing potion fire from level two. ⚠ **An exhausted spell stays in the list**, `disponible: false`, to be **greyed** — hiding it made players think they had lost it; the resolver refuses it. ⚠ **An object's cost belongs to the OBJECT, not the option type**: the list mixes free (potion, caltrops, smoke bomb) and paid (holy water, "instead of attacking"), so the option is `objet_libre` and `resoudreUsageObjet()` spends the action itself; the list holds only free items once the hero has acted. ⚠ The controller is now a **stack** (`feuilles`), and every back control **names its destination** — a back that returned to the action menu from targeting would make you pick the spell again; a tap on the backdrop pops one level; a new menu empties the stack. ⚠ **`POST /potions` is REMOVED**: drinking goes through `/choix` like everything else. Assumed consequence — no more drinking out of turn or at the hub; the emergency case stays covered by `MoteurReactions`, which offers the bag's potions when a hero falls. Two pre-existing defects fell with it: `ActionTab.creneauConsomme()` still thought `actionner_levier` was free (the server made it cost the action on 2026-08-24) and did not know `objet_libre` at all, so it would have greyed the new free option; and the concentration sheet read `parametres.sorts` while the engine published `sorts_epuises`, so the server's list was **never** consumed.

**Targeting is two-step.** An option that aims — `attaque`, `sort`, scroll — no longer *is* a target: `MenuMoteur` emits **one** `attaquer` (plus `lancer` when a throwable weapon has a target out of contact) carrying the legal targets in `parametres.cibles`, and the controller opens `CibleSheet.vue` — the sheet spells already used, now with an explicit "← Retour aux actions" (tapping the overlay worked but nothing said so). One option per monster flooded the menu from three enemies on and minted a mechanical id per target. ⚠ **`parametres.cibles` IS the whitelist**: the option id used to carry the target's legality, so validating the option against the last menu validated the target too — it no longer does. `resoudreAttaque()` checks membership and 422s otherwise; without it a client could hit any monster in the quest, out of range and out of line of sight (locked by `CoherenceMenuTest`). The dressed monster name and the "(à distance)" hint moved from the option label into the target entry (`nom`/`nom_base`/`distance`), and `GenererMenu::equivalentIa()` matches attacks by type alone — but **never dresses `lancer`**, whose label carries a mechanical fact (the weapon is lost) a paraphrase would erase.

**Equipment mastery (who may wear what).** Each weapon/armour row carries a `tag_equipement`; each class a base `tags_equipement` (`classes_heros`); and `deblocage` skill nodes whose effect is `{mecanique: acces_equipement, tags: […]}` add more. `Equipement::verifierAccesEquipement()` is the single gate — both the hub route and the in-quest equip action go through it. Tags now translate the deck's per-class restrictions one for one (doc 16 §2.2), eleven of them plus four `talisman_*`. Profile is **canon HeroQuest**: the **magicien** is limited to light and scholar weapons and wears no *ordinary* armour — lifted by *Cuir d'apprenti* / *Escrime de fortune* — but he is the **only** one who may wear bracers and the cloak of protection (`armure_magicien`), his first armour ever; and the two bruisers **both get everything from level 1** (René, 2026-08-22): barbare and nain each wear plate *and* swing two-handed weapons, no node to buy. They used to be **mirrored** — each specialty free, the other's paid for with a skill point (*Maîtrise lourde*, *Poigne de forgeron*) — and both nodes are now **deleted**. The elfe still gets neither. ⚠ Removing them from `CompetenceSeeder` was not enough: it uses `updateOrCreate` and deliberately never purges (a purge would detach nodes heroes already own), so a migration deletes the rows and their acquisitions — otherwise the tree would keep offering a node that opens nothing. ⚠ **Known debt**: this leaves the barbare alone at **4** tree nodes where every other class has 5 or more; `MonteeNiveauTest` records it at its floor rather than hiding it. `deux_mains` is **orthogonal** to the tag — it only forbids a shield, so the two-handed *Bâton* (whose card states no class restriction) stays the magicien's best weapon. A class with no declared tags means **no restriction** (fail open): missing reference data must never lock a hero out of their own starting gear. The check runs only when equipping — already-worn pieces are never stripped retroactively. This finished a design that had been declared in `CompetenceSeeder` since day one and never read: the engine used to test a hardcoded `necessite_maitrise_lourde` flag instead, so no class had any real equipment limit.

**The class CARD BACKS are now data** (René, 2026-08-22). Ten printed rules that no other data could imply — source facts, like the monster stat line. Two of them needed new columns, and both for the same reason: a fact was being inferred from another that merely overlaps it today.

⚠ **`objets.metallique`** — Bard, Druid and Rogue reason about *metal* armour, while the mastery tags say *weight* (`armure_legere`/`armure_lourde`). The catalogue holds only two ordinary armours and both are metal, so deriving it would work right now and break silently the day a leather armour is added — the Bard would lose his die with nothing to say so. Flagged on chain mail, plate, helm **and the Armour of Borin** (artefact, René's reminder). ⚠ The **shield is NOT flagged**: the cards name it separately from metal, and flagging it would quietly take the Druid's shield, which they never forbid him.

⚠ **`classes_heros.objets_autorises`** — the Monk wields only dagger, crossbow, handaxe, shortsword and staff. No tag combination says that: handaxe and shortsword share `arme_courante` with the broadsword, longsword and rapier he may not touch. A per-class whitelist that **replaces** the tag check when present, and applies only to pieces that demand a mastery — a potion is not a weapon. Re-tagging the five would have broken ten classes to serve one, `tag_equipement` being a single column.

The rest reuses what existed: **Berserker** loses `arme_distance`; **Rogue** loses his armour tag and starts with the **Bandolier** (which carries `compte_comme_arme: Dague`, making his Ambidextrie literal from turn one without occupying his off-hand); **Warlock** is aligned on the wizard's tags plus his own wand; **Knight** gets `Equipement::malusDeplacement()`, a single reader both `MenuMoteur` and `ResolveurTour` call — two exemptions to keep in step would have drifted, and the menu would offer squares the resolver refuses. ⚠ **Dwarf and Explorer disarm without tools**, and that is a *different resolution*, not a bonus: one die, and only a **black shield** fails. Giving them the ordinary Body check would have emptied the printed rule of its substance. The Bard's `bonus_des_defense_sans_metal` was already fully wired — only its notion of "metal" moved to the new column.

**The armoury is a CONVERSION of an equipment-card deck** (`reference/16_armurerie.md` §2.2, keywords in doc 19 §9). A physical card states its effect in one sentence — "This weapon allows you to attack diagonally", "Two-handed", "you have a 2 square movement penalty". Here that effect is *data*, so each sentence becomes stats (price, dice) plus keywords from a closed vocabulary, `App\Engine\MotsClesEquipement`. Doc 16 carries **two source tiers** that must stay apart: **§2.1 the booklets** (what the rest of the doc is opposable on — no price, almost no dice count), **§2.2 the deck**. The deck we port is **Sjeng / Ye Olde Inn** (`sjeng-equipment.pdf`, 27 cards, René's pick 2026-08-08) — and it says so on its own page 5: *"I have changed some item costs and functionality"*. ⚠ **The catalogue IS the official deck since 2026-08-15** — René's photos of the real Hasbro cards (20 equipment + 15 potions, each stamped © 2021/2022/2023) are transcribed card by card in **§2.1bis**, from the project's Drive folder [`1seESGzXRhVw7ijIPuRVisaE36BPPoJ53`](https://drive.google.com/drive/folders/1seESGzXRhVw7ijIPuRVisaE36BPPoJ53) (public link, readable over plain HTTP via `embeddedfolderview` — the Drive MCP connector is *not* authenticated here). §2.1bis **outranks §2.2**, which is now a historical annex, and it settled the oldest dead end in the doc: prices do exist. **Twelve pieces left the catalogue** — cane, sling, whip, both bows, spear, halberd, mace, flail, greatsword, bastard sword, cloak of protection: the fan deck invented them, and `ArmurerieConformeTest`'s list of "off-source" pieces, seventeen names long, is now **empty** and must stay so. Ten were repriced (dagger **150 → 25**, bracers **200 → 550**), the **staff fell from 2 dice to 1** — its card's number, which costs the magicien his best weapon — and the **bracers turned out to have no class restriction at all** where we reserved them to the wizard. Three of our own claims were falsified on the way: the *Handaxe*, *Battle Axe* and *Chain Mail* all have official cards, where §2.1 and a `GroupeController` comment said the hatchet "exists nowhere in the official material"; only the **spear** is still untraceable.

**Nineteen items entered with a reader each** (the condition René set: keep the cards *and* make them work). Four are hardware — **caltrops** (a runtime `carte.grille['chausse_trappes']` layer, one combat die on entry, white shield to keep going), **smoke bomb** (the monster leaves `$occupees`, which lifts movement blocking AND line of sight in one gesture, since that set is the engine's only occupancy loop — but ⚠ *traversing is not stopping*: ending a move on its square is refused), **holy water** (kills undead by `monstres.nom_base`, never the AI-dressed name), **bandolier** (`compte_comme_arme`: no extra die, only the rules that *require* a dagger — the Rogue's Ambidextrie, and closing the Monk's bare-handed techniques). Fifteen are potions, and three of them carry a **class restriction — a first for a consumable**: `MoteurPotions` consulted no right at all, since a consumable never goes through `equiper()`. The decision is extracted into `Equipement::estAccessible()` and applied at the **three** places that must agree — the resolver *refuses*, `/moi` *badges* (`utilisable`, greying the button — a hero may carry a companion's potion), `MoteurReactions::soinsDisponibles()` *filters* (offering an emergency heal the resolver would refuse is worse than offering none).

Twelve keywords were added to `MotsClesEquipement`, each with its reader, plus a **seventh duration**: `plus_de_monstre_en_vue`, which the barbarian's two potions need and `fin_du_combat` cannot say — the latter reasons over the whole quest, the former over the bearer's **line of sight**. ⚠ It is evaluated at the **start of the turn** (`MoteurSorts::rythmerBuffsDeVue()`, same hook as the Monk's style recovery, same idempotence guard), which both expires the buffs *and* **re-arms** Battle Rage's second attack — without that guard, re-arming after every action would grant a third attack.

**Artefacts are a CONVERSION too** (`sjeng-artefacts.pdf`, Ye Olde Inn — 34 cards from five sources; doc 16 §9.1, René's pick 2026-08-09). They replaced **7 artefacts we had invented**, and the reason matters: those were seven weapons that only climbed the dice curve — 4, then 5, then 6. A real artefact doesn't raise the curve, it does something nothing else does. The 6-dice *Fendoir des Titans* made the whole armoury moot the moment you found it; the *Lame des Esprits* that replaces it rolls 3 — except against undead. Nine cards are ported (3 weapons, Borin's Armour, 5 talismans), each with a real reader: `degats_fixes` (no dice, no defence — the only key that bypasses `Engine\Combat`), `des_attaque_contre` (**replaces** the weapon's dice, per the card's "OR"), `attaque_double_contre`, `bonus_pv_body_max` / `bonus_pv_mind_max`. The two "contre" keys test `monstres.nom_base`, the **catalogue** name — never the AI-dressed one, or the blade would stop recognising undead the first time a quest is narrated. Twenty-five cards are **deliberately not seeded**, each listed with the mechanic it needs (spell economy, damage types, charges, teleport…): a card whose central effect the engine ignores is a rule promised and never kept. A fifth slot, `talisman`, carries the four class jewels — they grant max HP, not dice, so neither `armure` nor `casque` fitted without making them compete with real armour. `DeckFouille::choisirArtefact()` now draws weapons **and** armour, and rejects anything no **active class** could ever wear (crossing `tag_equipement` with class tags + `acces_equipement` nodes) — that generalised a hardcoded barbarian check and is what stops a quest's only chest from paying out Dwarven Runestones to a party with no dwarf. Fixing the menu was part of it: `MenuMoteur` gated the whole action block on `! $aAgi`, so **the Potion d'héroïsme's second attack had never been reachable** — the resolver accepted it, but no menu ever offered it and the controller rejects options absent from the last menu.

**Two weapons in hand — the off-hand grants a CHOICE, not a die** (René's call, 2026-08-12; doc 16 §2.2, doc 01 §7). Four loadouts, and only four: two one-handed weapons · one two-handed weapon · one one-handed weapon + shield · one one-handed weapon alone. This had been blocked twice over, and the second blocker was the real one: *no card says what the second weapon grants*, so wiring it meant inventing the one number that matters. René's answer removes the number entirely — the off-hand adds **nothing** to the dice, it adds an attack **option**. The menu therefore emits one attack per weapon ("Attaquer — Épée large", "Attaquer — Dague"), each carrying **its own** legal targets, because reach, diagonals and throwing belong to the WEAPON, not the hero: a crossbow sees the room, a sword its four neighbours, a longsword adds the diagonals.

The first blocker is gone too: `Equipement::slotsPossibles()` returns **two** slots for a one-handed weapon, so the slot becomes a parameter — of the API (`POST /equipement {emplacement?}`), of the in-quest menu (`equiper_{id}` / `equiper_{id}_gauche`) and of the controller (two buttons). ⚠ Dice are read **per weapon**: the `des_attaque` column stays the reference — it carries class, main-hand weapon, Forge and passive nodes — and striking left-handed swaps only the *weapon's share* of it (`desAttaqueAvec()`); recomputing the whole thing would drop everything else on the floor. `frapper()` takes the inventory line used, and with it the Vindication arrow, the thrown weapon (that one is the one lost) and the targeting keywords. Two intended side effects: the Rogue's **Ambidextrie becomes literal** ("one additional attack *with a dagger*" — that's why René wanted this), and **"unarmed" now looks at BOTH hands**, so a dagger on the left closes the Monk's bare-handed techniques — a shield does not, it never strikes (`Equipement::armesEnMain()`).

**Charges and spell economy** (`config/cartes.php`, doc 19 §9, René's call 2026-08-09) — the two mechanics that were blocking seven cards, opened together because three of those cards need both. A **charge** says "this copy has N uses": `inventaire.charges`, not `quantite` (which counts identical copies — a four-arrow bow is one object used four times). `null` means *never touched*, not spent, so every path that creates an inventory row (market, chest, gift, loot) stays ignorant of charges; at zero the piece goes **inert** — it stays in the bag, its effect stops. Nothing is destroyed: an item vanishing on its own would be a surprise, not a rule. `MoteurCharges` is the only reader. **Spell economy** is the pivot `personnage_sorts.disponible`, which was a bare boolean reset per quest, with the only two exceptions being skill *nodes* (Concentration returns one spell, Réserve arcanique grants a second cast) — no object could touch it. Now: `restaure_sorts` (all spells back — the scale is what makes the card worth finding), `second_sort_par_tour` (the node's power on an object; both share `etat.bonus_sort_utilise`, so they don't stack), `sort_non_epuise` (one spell spared for one charge), `sort_non_epuise_sur_bouclier_noir` (a die after each cast, 1-in-6). ⚠ **Order matters**: the rod is rolled *before* the ring is spent — succeeding on a free effect must not burn a scarce one. The Spell Ring diverges deliberately: the card picks the spell at quest start, we pick it by casting — same outcome, no blind bet before seeing the dungeon. The chest also gained a fallback: a **consumable** artefact rather than gold when every portable one is already held, which is what finally gave the Anti-Poison Quill a way into the game (it needed no mechanic at all, only a channel).

**Damage now has a NATURE** (`App\Engine\TypeDegat`, doc 16 §4.5 / doc 19). `effet.type_degat` sits on the SOURCE (a hero spell or a Dread spell); a nature is only worth declaring when it has **a source AND a reader**. **`feu`** has both — sources Boule de Feu / Trait de Feu / Tempête de feu, readers the **Anneau de Feu** (2 charges, each fully negating a fire spell) and the **troll's regeneration**, which a burn stops for good (`instances_monstres.brule`). **`froid`** is declared **with no source**: the six Frozen Horror cold spells are *named* by the booklet (doc 18) but their effects exist nowhere we have, so the Armband of Ice and Ring of Warmth stay unported — no longer for want of a mechanic, but for want of anything to resist. `MoteurSorts::absorbeDegat()` is the **single** reader for both paths that hurt a hero (a hero's spell in friendly fire, and a Dread spell): the card says "Fire **or Chaos Fire**", and a ring protecting against one fire in two would be worse than no ring. Troll divergence, stated: the card makes only fire-inflicted Body permanent, which would need per-nature damage accounting — here a burned creature simply stops regenerating.

**The 8 base monsters are finally SOURCED** (`sjeng-monsters.pdf`, doc 16 §4.4, René's pick 2026-08-09). Doc 16 had carried "⚠ non trouvé" across the whole stat table since day one, because the monster chart lives on the GM screen — cardboard, never digitised. The deck gives it, and **two independent cross-checks** validate it against the booklets: the Quest 1 mummy "rolls 4 Attack dice **instead of 3**" (LQ p. 5) matches the card's 3; and *Sleep* "may not be used against mummies, zombies, or skeletons" (LR p. 8) is explained by those three — and only those — having **Mind 0**, which our engine already treats as immunity to Mind rolls. The rule wasn't an arbitrary exception, it was a consequence of the stat. ⚠ **Balance shift**: on the board *every* base monster has **1 Body** — goblin and gargoyle alike. We had given 2-3 to the tougher ones, so the bestiary got markedly more fragile; `cout` was rebalanced with it. That is the board's design (heroes soak, monsters drop in one hit) and it's what makes the `sous_boss`/`boss` tiers — which remain ours — legible. The **official expansion creatures** followed on 2026-08-10 — 23 added, 3 realigned (doc 16 §4.6) — and their stats come **not from the fan cards but from `reference/18_extensions.md`**, which takes them from the Hasbro booklets. That matters: the two sources contradict each other (the deck gives the Ice Gremlin 2 Body instead of 3, the Polar Warbear 3+3 dice instead of 4+4). **The booklet wins**, as everywhere else in doc 16. `tier` and `cout` are the only values of ours — the encounter budget doesn't exist on the board. Two additions reshape the tiers: the **Seigneur ogre** (10 Body) takes the top of `boss`, and the **Archer elfe** gives the bestiary a second ranged creature ("Attack 4 (1 if adjacent)" — exactly what `portee`/`attaque_distance` already expressed). **Not seeded**: the *Abomination* (doc 18 marks it †: its stats are in no booklet, only in another box's tournament table), the named Jungles of Delthrak traits (*Agile*, *Venomous*, *Clever Tactician*, *Entangling Roots*, *Spawn* — no reader, so the stat block is seeded **without** the trait rather than with a capacity nothing applies; note that our `invocation` capacity summons what the *spell* says, i.e. undead, so giving it to the Serpent would make it spit skeletons), and the ~50 non-official cards (Skaven, Gnoll, Bugbear, Carrion Crawler… Warhammer/D&D, never HeroQuest). `BestiaireSourceTest` freezes both sourceable sets and rejects any capacity without a reader.

**Expansion TRAITS are now in the engine, not just the catalogue** (doc 16 §4.7 — Jungles of Delthrak p. 48-49, rules quoted in doc 18). Four of the booklet's five keywords are ported: **`agile`** (`Grille::autoriserFranchissement()` — furniture and figures stop blocking, **walls don't**: the card says terrain and creatures, not stone; it is the exact inverse of `autoriserLaRoche()`), **`racines_entravantes`** (`ResolveurTour::tronquerSurRacines()`, plugged in where traps already truncate a path — and note it must also rewrite `$x`/`$y`, because further down the arrival falls back to the *requested* destination when no trap stops the hero; shortening the path alone let him teleport to his goal while looking stopped), **`venimeux`** (condition *Envenimé*, resisted on a **raw d6 ≥ 5** — not a combat face, since ours merge 4-5 into a white shield and would swallow half the rule — and only when the blow actually landed), **`tacticien`** (the +1 flanking die; the attacker is not its own flank, and a defeated or unrevealed monster flanks nobody). **Spawn** and Clever Tactician's second move landed on 2026-08-10 too, alongside **`ethere`** (Rise of the Dread Moon). *Spawn* names its offspring in the capability (`['spawn' => ['creature' => 'Rejeton putride']]`) precisely because `invocation` summons what the *spell* says — undead — and would have had the serpent spitting skeletons; "as an alternative each turn" is the **only** written limit, so no population cap was invented, laying an egg simply costs the turn's action. The tactician's **retreat** is our reading of a permission the booklet leaves open ("may move before *and* after its action"): staying in contact would gain nothing from a second move, so he steps out of reach, and stays put if no free non-adjacent square exists. **Ethereal** is two halves in two places: `Grille::autoriserEthere()` erases rock, doors, furniture and figures, but the grid cannot carry the rule's two prohibitions — `derniereCaseOuSArreter()` walks the path back to the last genuinely free *and discovered* square, because traversing is not overlapping and a creature must not go and sit in a room the party never opened; and `Engine\Combat` takes `defenseurEthere`, counting **black shields instead of skulls** — one face in six instead of three, the only rule in the game that changes a die's success condition. The "except by spell or artefact" exception is taken literally: a `unique` weapon hits normally, and spells go through `sortDegats` anyway. Trap immunity was already free (`MoteurPieges::declencher()` takes a `Personnage`). The Spawnling's **deferred damage token** is in too, once René supplied the missing removal rule (doc 16 §4.8): **you attack them**, and a hero *adjacent to another hero* targets the token rather than the companion. Full cycle: the serpent lays a Rejeton (`spawn`) → on its turn, in contact with a hero, the figure leaves the board and becomes a token (`s_accroche`, `etat_personnage_quete.jetons_rejeton`, **cumulative**) → at each of the carrier's turn ends it deals **1 Body per token, automatic and undefendable** — the only damage in the game that rolls no dice at all → a neighbour tears them off, **one per skull**, a figure derived rather than invented from the Rejeton's own stat line (Body 1, Defence 0: nothing to parry with, falls to the first point). ⚠ **Distance 0 or 1, never more**: the carrier may deal with their own, and any hero **in contact** may tear a companion's off — but nobody pulls a spawnling across the room. An isolated carrier is therefore not doomed, though spending the action on it is a turn not spent fighting. It also **has to be visible** (René's requirement): `EtatGroupe` exposes `jetons_rejeton` per hero, the manette renders a red badge beside the conditions, the table prints it on the inspected figure. Automatic damage that nothing announced would be unplayable, and it is the neighbour who must decide to come and help. The counter lives on the **quest** state — spawnlings are filth you pick up in a dungeon, not an infirmity you carry between campaigns. **Side effect worth knowing**: porting Venomous forced wiring `conditions.effet.deplacement_interdit`, a catalogue key that had lived since the table was created **with no reader at all** — an "Immobilisé" hero walked normally. `MenuMoteur` now drops "Se déplacer" and `ResolveurTour` refuses the move, which finally makes *Immobilisé* immobilising. `TraitsExtensionsTest` exercises all four **in play**, not in the catalogue.

**The card registry is TESTED, not declared** (`config/cartes.php`, 61 cards across both decks). `CartesSourcesTest` checks it against the catalogue **both ways**: every card marked ported must exist in the DB, and no weapon, armour or artefact may exist without a card — two named exceptions, the tool kit (booklet, LR p. 19) and the healing vial (treasure deck). So "the catalogue comes from the cards" is a property, not a documentation claim. The same registry feeds `GET /api/guide`, hence the **/guide → "Cartes sources" tab**: players see where each piece comes from *and* the 26 board cards that have no mechanic yet, each with the exact thing it needs. When you port one, move it from `manque` to `objet` in the config — the test then forces the seeder to follow. Reference docs to keep in step: `reference/16_armurerie.md` §2.2/§9.1 (card by card), `04_market.md` (catalogue tables), `01_personnages.md` (slots + mastery tags), `docs/contrat-api.md` (/moi payload, /api/guide). `docs/plan-*.md`, `docs/verdict-*.md` and `docs/correctifs-restants.md` are **dated records** — they carry a banner saying so and are deliberately not updated.

**Effect durations are a vocabulary, not free text** (`App\Engine\DureeEffet`, full reference in `reference/19_mots_cles_effets.md`). A spell's or item's `effet.duree` says **when its buff ends**, and six keywords are legal: `prochaine_attaque` · `prochaine_defense` · `premier_degat_subi` · `ce_tour` · `prochain_tour` · `fin_du_combat`. An **integer** means something else entirely — a countdown in *turns*, decremented at end of round by `decrementerDurees()` (that's what `conditions.duree_defaut` carries). `duree_defaut = 0` does not mean "instant" but "no counter": expiry comes from a trigger. The key had **no reader at all** until 2026-08-05 — the few effects that expired did so via hard-coded calls on their *effect key* (`consommerBuffs($p, 'bonus_des_attaque')`), which conflates what a buff does with when it stops. Two consequences, both seen in play: there was no `consommerBuffs('bonus_des_defense')` **at all**, so the Potion de défense and Peau de Pierre lasted **forever**; and the Potion de rage, sold as "un combat", died on the first attack like Courage. `MoteurSorts::expirerBuffs()` is now the authority and **re-reads the duration from the source** (`sort:{Nom}` / `potion:{Nom}`) at expiry time, so fixing a catalog value applies to buffs already in play. `ce_tour` vs `prochain_tour` is a **mechanical** distinction, not a synonym: the monster phase sits between them — `ce_tour` ends when the hero ends their turn (never reaches the monsters), `prochain_tour` ends at the round boundary *after* the monster phase, which is the whole point of a protection like Voile de Brume. `fin_du_combat` means **no monster still engaged** — no instance that is both `etat = actif` **and** `revele = true` (René's call). It is *not* "no monster left in the dungeon": `etat = actif` only means "not yet defeated", and a quest keeps active-but-unrevealed monsters behind every door never opened, so conflating the two would stretch a "one combat" buff across the whole descent. Clear the room, the combat ends; opening a door further on wakes sleepers and starts a **new** one. `combatTermine()` holds the definition, `verifierFinDuCombat()` (idempotent) applies it after every hero action, after the allies phase and on victory — and the cleared-dungeon path delegates to it rather than duplicating the test. Adding a duration keyword without wiring its trigger creates an effect that never ends — declare it in `DureeEffet`, anchor it, document it. Separately, `conditions.effet.fin` (`jet_mind_reussi`, `reveil_ou_attaque`…) stays **descriptive and unread** — it names events already hard-coded elsewhere; don't mistake it for an active vocabulary.

**A duration is not a REGAIN, and damage is now interceptable** (`App\Engine\RegainEffet`, `App\Partie\MoteurDegats`, doc 19 §4bis/§4ter). Three different things sit side by side and used to be conflated: `effet.duree` says when the **buff** stops, `personnage_sorts.disponible` whether the **spell** can be cast again, and the new `effet.regain` **on what event it becomes castable again**. Saying a spell "lasts until you kill a monster" would be false — the buff ended long ago, it is the *right to recast* that returns. `disponible` used to recharge only on the next quest or via two hard-coded skill nodes, so no **data** could express what the official cards state constantly ("Regain this spell when you reduce a monster's Body Points to zero"). Three events, all with a reader: `body_au_max` (observed on any **rise** of `pv_body`, mirroring how `premier_degat_subi` observes the fall), `monstre_vaincu` (the **killer** recharges, not the party), `allie_deux_boucliers_blancs` (⚠ "any hero you can see, **excluding yourself**" — the caster must not recharge on their own parry, and must have line of sight; white shields only, since that is the face that parries for a hero). The three spells that will carry them — *Shapeshift*, *Demonform*, *Inspiring Tale* — wait on their classes, and `RegainEffet::SANS_UTILISATEUR` names that debt exactly as `TypeDegat::SANS_SOURCE` does for cold. Separately, hero damage now funnels through `MoteurDegats::infligerAHeros()`, which emits `HerosVaSubirDegats` **before** writing: `degats` is mutable, a listener may reduce it to zero (never raise it), and the applied amount is what gets journalled — payloads publish `$subis` and the re-read `pv_body`, never `$resultat->pvBodyApres`, which `Engine\Combat` computed before any reaction. This is what makes *Dark Wings* and *Twisting Torrent* portable; ⚠ only the **engine** half exists — asking a player "cancel it?" mid monster-phase is beyond the game loop, so an automatic listener works today and a *choice* does not. `Personnage::booted()` stays as the safety net for any path that writes `pv_body` directly: one intercepts, the other observes.

**Out-of-turn reactions — the player decides, mid monster phase** (`App\Partie\MoteurReactions`, `POST /groupes/{id}/reaction`, contract §Réactions hors tour). *Dark Wings* and *Twisting Torrent* trigger **when their bearer takes damage**, i.e. during a monster's turn — the only action in the game that happens outside its author's turn, which is why it has its own route: there is no menu at that moment, and `/choix` assumes it is your turn. **The order is deliberate**: the monster phase resolves inside *another* player's HTTP request, inside a transaction, and nothing can suspend it for a round-trip to a phone. So the blow is **applied**, then the question is asked — exactly the table's order, where damage is announced before the player says "I cancel that"; accepting **undoes** the blow. `MoteurDegats` applies damage → `proposer()` writes `etat_personnage_quete.reaction_en_attente` if the hero has an **available** reactive spell → `.reaction.proposee` goes to the **private** `joueur.{id}` channel → the controller shows `ReactionSheet.vue` with a countdown. The pending offer is **also** exposed in `EtatGroupe.entites[]`: a controller reloaded meanwhile would otherwise lose the offer, and with it the player's power, with nothing on screen saying so. Accepting restores the HP, **stands the hero back up** if that blow felled them, and spends the spell (`disponible = false`) — which is what stops every blow being cancelled; refusing keeps it. Either way the offer is consumed, or the sheet would pop back on the next refresh. **Six actions** exist now, and the offer carries which one in `action`: `annule_degats`, `plancher_pv` (Chevalier — offered *only* on a fatal blow), `annule_degats_voisin` (offered to the PROTECTOR, HP restored to the victim), `riposte` (Berserker — cancels nothing, strikes back; adjacency re-checked at resolution) and `defi_errant` (the only trigger that is **not** a blow taken: a wandering monster surfacing from a search card, `degats: 0` — read `action` before writing "you just took…"), and `soin_urgence` (René's call, 2026-08-13 — the hero just **fell**, and spends a potion or a healing spell to stay standing). ⚠ `soin_urgence` is the only one that **undoes nothing — it pays**, so it fires on *any* cause of the fall, traps and spawnling tokens included: `SOURCES_REACTIVES` answers "which blow may be cancelled", and refusing a potion to a hero who fell down a pit would make no sense at the table. It is offered **last**, after every free capacity (*Inébranlable* costs no item, better it goes first), and only at 0 PV — a hero still standing will drink on his own turn. The offer carries `soins: [{cle, type, nom, soin}]`, potions first, and that list **is the whitelist**: the player answers with `soin` and an unknown key falls back to the first entry, never to a companion's bag. Reactive sources are `attaque_monstre`/`sort_dread`/`tir_ami` — ⚠ **never `rejeton`**: the cards speak of a blow taken, while spawnling tokens are automatic bleed at the end of your *own* turn, and letting a reaction cancel them would hollow out the token mechanic. **The TPK now WAITS for the answer** (2026-08-13). A blow that felled the **last** standing hero used to close the round as `echouee` before the phone had rung: the offer landed on a quest already lost, and the most dramatic moment of the game played out without its player. `ResolveurTour::verdictDeChute()` returns three verdicts — `debout` / `suspendu` / `tpk` — and **suspends** while any pending offer could still bring someone back (`ReactionEffet::ACTIONS_RELEVANTES`: the two cancels, the HP floor, the emergency heal; *not* riposte or the knight's challenge, which strike rather than revive). The verdict is re-taken on every resolution path, accept **or refuse** — refusing is what pronounces the TPK. ⚠ A suspended round takes **no `nouveau_tour` snapshot**: an "everyone on the floor" snapshot would become false the moment the potion is drunk, and that is the one `/reprise` would reload. ⚠ And a server-side expiry **reaches no client** — the same lesson as the "MJ réfléchit" lock: `MoteurReactions::rattraperExpiration()` consumes stale offers and re-takes the verdict, called from the table heartbeat (the only reliable ticker) and from `GET /etat` (for a game played with no table screen). Without it, a silent phone would freeze the group on the floor, in-quest, forever.

**Card capacities of the extension classes are IN PLAY, not in the catalogue** (`App\Partie\CapacitesInnees`, `App\Partie\StylesElementaires`, doc 01 §4ter). The 17 capacities of the 6 classes that have them are wired, each to a real reader; Druide and Warlock have none — their cards are *spells*. They come free with the figure (`competences.innee`), and the counters are the point: `capacites_utilisees` (per quest, dies with the quest state), `capacites_tour` (per **turn**, cleared where `a_joue` is), `styles_epuises` (the Monk's third rhythm, which **recharges mid-quest**). Adding a "once per X" without wiring its counter turns it into "once per campaign" or into no limit at all — that is exactly what `bonus_des_attaque_flanc` did until its counter existed.

`ResolveurTour::frapper()` is the **single** strike core: menu attack, Furie, sweeping strike and out-of-turn riposte all go through it, because recopying the dice maths per entry is how a bonus ends up applying "in some places" (the seven-way defence split that `desDefenseHeros()` fixed). Range and line of sight stay with the CALLER — they don't mean the same thing on each path. `StylesElementaires::sourceActivable()` arbitrates the mechanics with **two** sources (`attaque_balayee` is both the Berserker's *Frénésie* and the Monk's *Œil du Cyclone*), so menu and resolver always answer the same question.

Three porting decisions, each stated where it is taken: the **Furie** caps at `pv_body - 1` (a capacity promising an *immediate* attack cannot fell its bearer first); **Ambidextrie**'s second strike was resolved by porting the off-hand slot itself, so the dagger is now really held; **Parler à la Pierre** grants an automatic search, because our "Fouiller la zone" already searches traps AND secret doors in one action (doc 14 §3.1) — the card's promise is our default, and a technique that costs a Style to do what everyone gets free is a rule promised and never kept. The Monk's recovery is taken **literally** — no monster *in his line of sight* at the start of his turn, not "the dungeon is clear" — and the Fire lock does the rest: his strongest strike only arrives after a real fight. ⚠ A technique played **out of turn** (*Torrent Tournoyant*) exhausts its element but does **not** eat the coming turn's activation: "once per turn" governs what you do on YOUR turn.

Every one of them is **visible**: a swept strike announces itself in the combat log before its volley, the Explorer's trap warning prints a line (Zargon warns out loud at the table — but no tile is placed, the trap stays `cache`), and each new option type carries its own icon on the controller. An automatic effect nothing announces is unplayable — same rule as the spawnling tokens.

**Talents are a GRID: 3 columns × 3 rows per class** (`competences.categorie` / `colonne` / `rang`, `App\Engine\MotsClesTalent`, `App\Partie\Talents`, doc 01 §6 — René's call, 2026-08-23). A column is a **category named by the class itself** (« Furie » for the barbare, « Traque » for the explorateur — free labels, no shared vocabulary), and buying row *n* requires row *n−1* **of the same column**. `prerequis_id` keeps its meaning and is now **computed** from `(classe, colonne, rang − 1)` instead of named by hand, which makes a chain across two columns structurally impossible and leaves `CompetenceController::acquerir()` untouched. Nine cells for the 4-7 points a campaign yields: you go down a column and give up another. The three nodes of a column are **different effects of the same domain**, not one number growing — the chain is an order of acquisition, not a power curve. The 17 `innee` card capacities stay **outside** the grid (`colonne`/`rang`/`categorie` null): they come with the figure and cost no point, and putting them in a cell would claim otherwise. The former « barbare alone at 4 nodes » debt is settled by construction.

⚠ **Talents are read by MECHANIC, never by node NAME** — that recabling was the precondition of the whole rework, and it repaired fifteen mute nodes. The engine used to look for `'Garde tenace'`, `'Coup puissant'`, `'Intimidation'`, `'Réserve arcanique'`, `'Concentration'`, `'Désamorçage'`, `'Tir précis'`, `'Œil du mineur'`, `'Contresort'`, `'Forge'`; the extension classes carried the **right** `effet.mecanique` under other names — *Esquive*, *Garde haute*, *Écorce*, *Refrain vaillant*, *Prestance*, *Méditation*, *Cartographe*, *Bras d'acier*, *Coup sauvage*, *Second couplet*, *Rappel*, *Communion*, *Doigts de fée*… — and **did nothing at all**, while `CompetenceSeeder` promised in comment to use "only mechanics that already have a reader". True of the mechanic, false of the wiring. `App\Partie\Talents` is now the single reader (`a()`, `noeud()`, `valeur()`, `disponible()`, `consommer()`), and `CapacitesInnees` extends it — a card capacity is just one competence among others. ⚠ `noeud()` takes **criteria** on `effet`, and that is not cosmetic: `bonus_des_attaque` names both the permanent bonus already banked in the column *and* the Frénésie that only counts under half HP; reading them undistinguished applies one for the other. Two **class** gates fell with the recabling (`magicien` for Concentration, `nain`/`explorateur` for disarming): owning the node is what decides now, and a `desamorcer_piege` talent **grants** the right rather than only softening the failure.

⚠ **Three locks keep talents from being decorative, and all three are automated.** (1) The **text**: every node carries a hand-written `description` (the gain, its condition, its cadence) *and* an `avantage` **derived from `effet`** by `MotsClesTalent::avantage()` — never typed, so it cannot disagree with the mechanic. Both are published (`/api/competences`, `/api/guide`) and shown side by side on the talent sheet; a test demands ≥ 25 characters, the number when `effet.valeur` exists, and the cadence when `effet.frequence` does. The display vocabulary lives **server-side** on purpose: `store/game.js` held its own table keyed on *column* names (`pv_body_max`), so a competence `effet` produced **no chip at all** — every talent showed without a single figure and nobody had noticed. (2) The **registry**: `MotsClesTalent::MECANIQUES` maps each mechanic to `lecteur` + `libelle` + `icone`, is checked **both ways** against the seeder, and — the assertion that was missing — each declared reader's class and method must exist *and* at least one of them must **name the key in its own file**. `CapacitesInnees` used to declare its readers with nothing verifying the link, and four of them (`plancher_pv`, `annule_degats`, `annule_degats_voisin`, `defi_errant`) pointed at a file where the word never appears — the key lives as a constant in `App\Engine\ReactionEffet`. "At least one" and not "all", because some sites *apply* a rule without naming it: `Grille::autoriserFranchissement()` only receives a boolean. (3) The **proof in play**: `TalentsEnJeuTest` exercises one case per mechanic through the real engine and real routes, `TalentsRecablesTest` replays every recabled reader **on a class that is not the historic name**. Corollary, assumed: a mechanic without a case there is not seeded — better a cell reusing a proven effect than a talent that does nothing.

⚠ **Twenty-one new mechanics came with the grid, each with its reader** on an existing seam: `ResolveurTour::frapper()` (`bonus_des_attaque_distance`, `bonus_des_attaque_contre_tier` — read from the **catalogue** `tier`, never the AI-dressed name —, `bonus_des_attaque_apres_deplacement` — gated on `a_deplace`, since `deplacement_tour` is fixed at menu generation and an immobile hero looked like he had sprinted —, `ignore_defense_monstre`, `attaque_supplementaire_apres_kill`, `inflige_condition_sur_touche`), `MoteurDegats::infligerAHeros()` (`reduction_degats`, applied **after** the interception listener so a cancelled blow still reaches zero, and never on `SOURCE_SACRIFICE`), `MoteurSorts::absorbeDegat()` (`resistance_degats_type`, read **before** any charged item so a permanent talent never spends one), `ResolveurTour::resoudreAttaqueMonstre()` (`bonus_des_defense_contre_distance`, `bonus_des_defense_allie_adjacent` — neighbours only, never its bearer —, `malus_des_monstre_adjacent`), `ResolveurTour::sortDegats()` (`bonus_degats_sort`, via `ResultatAttaque::avecDegatsAjoutes()` so `degats`/`pvBodyApres`/`cibleTombee` recompute in one place, and never on a fully parried spell), `MoteurSorts` (`regain_sort`, reusing `App\Engine\RegainEffet` rather than a second grammar, and rendering **one** spell; `sacrifice_pv_pour_sort`, refused at 1 PV), `MoteurPortes::detecterSecretesAdjacentes()`, `ResolveurTour::tronquerSurRacines()`/`tronquerSurChausseTrappes()` (`ignore_terrain_entravant`), `Quete::aFouille()` (`fouille_supplementaire`, extra entries suffixed `#n` because entries are de-duplicated), `RareteButin` via the searcher's level (`rarete_butin_amelioree` — one curve advanced, not a second invented), `PhaseMarche::ouvrir()` (`remise_marche`, the group's **best** discount and not their sum, since the purse is shared), `relance_jet_mind_rate`, and a new action option `soin_allie` (1d6 to a hero in contact, which **stands them back up**; `option.parametres.cibles` **is** the whitelist the resolver re-validates). ⚠ Adding a mechanic means writing its reader, its registry line and its in-play test **before** the data — the same rule the armoury and the spell vocabulary already obey.

**ÉPREUVES: anchors on the map that ask for an ATTRIBUTE ROLL** (`epreuves` table, `cartes.grille['epreuves']`, `App\Engine\MotsClesEpreuve`, `App\Partie\MoteurEpreuves`, doc 14 — René's call, 2026-08-24). They exist because of a measured hole: since `MenuChoix` was deleted (2026-08-18) the engine emitted **one single roll**, « Fouiller la zone » (Mind, `perception`), so the contexts `savoir` and `social_peur` had **no producer at all** and six grid talents — *Intimidation*, *Érudition*, *Prestance*, *Beau parleur*, *Méditation*, *Cartographe* — never fired in play. `CLAUDE.md` had announced the fix in advance: *« flavour actions come back anchored to elements placed on the map at creation time, resolved by the engine the way levers already are »*.

A trial is a seeded catalogue row (7 of them) dropped on a floor cell by `AssembleurCarte::placerEpreuves()` — fourth layer, exact pattern of `leviers`/`pieges`/`mobilier`, **no coordinates in the gabarit** (that is the levers' lesson: `placerLeviers()` demanded an x/y procedural placement cannot know, so **no gabarit ever declared one** and `actionner_levier` was never reached). The menu emits it as **`type: 'jet'`**, and that is the whole point: `resoudreJet()` then applies the context advantage and the Mind re-roll for free. ⚠ **One attempt per hero**, win or lose (`tentee_par`, the `fouille_par` pattern) — the real price is the action slot, and companions keep theirs. Six effects, closed vocabulary checked both ways with its readers confronted to their files: `or`, `objet`, `parchemin`, `soin_groupe`, `retire_condition`, `desarme_pieges_salle`. ⚠ `exige_placement` is a **placement precondition**, deliberately NOT inside `effet`: the *Autel fêlé* only lands in a room that has a trap — disarming an empty room is a reward the player pays an action for without being able to know it. ⚠ The gold does **not** go through `appliquerButin()` although the gesture is identical: the Explorer's *Chasseur de trésor* adds 25 « whenever a SEARCH CARD rewards you with gold », and a trial is not a card.

⚠ **`attribut_body` got three employments, and a ceiling** (René, 2026-08-24). It only ever touched two rare situations — a detected trap you are allowed to disarm, a pit on your path — so three grid nodes (*Colosse*, *Ancré*, *Corps aguerri*) were buyable and nearly inert. Now: **pushing an enemy** (option `repousser_{id}`, difficulty = the creature's **catalogue** Body PV, never its current ones — a wounded boss is no easier to shove — and ⚠ **no trap fires** under the pushed figure, since `MoteurPieges::declencher()` takes a `Personnage`); **smashing furniture** (`mobiliers.difficulte_destruction`, ⚠ `null` means **indestructible**, not "unset" — the tomb is a stone sarcophagus; the piece stops blocking movement AND sight in one gesture because `FabriqueGrille::pour()` holds the single furniture loop, and a **searchable** piece destroyed yields **one last search** to its destroyer even if the whole party had already emptied it); and **forcing a lever**, which now demands a Body roll and **costs the action slot** where it used to be a free interaction. ⚠ The lever roll is **retryable without limit**, unlike trials — that is exactly what lets a room hang on that single lever without ever sealing itself.

⚠ **`App\Partie\DifficulteBody::plafonnee()` is the single point of passage**: no Body difficulty ever exceeds the best `attribut_body` among the **engaged** heroes. A roll the party cannot mathematically win is not an obstacle, it is a dead end dressed as a choice. ⚠ The **raw** value is stored (catalogue, lever), the ceiling applies at **menu generation** — it rises when someone buys *Colosse* and falls when the bruiser leaves, so freezing the effective figure in the data would make it lie by the next level. All five producers go through it, the two historical ones (disarm 1, pit jump 2) included: one rule, one place. Fail open with no party to ask — a missing reference must never silently harden *or* soften the game.

⚠ **A room may now hang on a single SECRET DOOR** (René, 2026-08-24) — objective room and artefact chest included. `AssembleurCarte::secretiserUneAreteDArbre()` makes **one** spanning-tree edge secret (a leaf, never the one leaving room 0) and **drops any loop that would serve that room** — without that last step the feature fired in **5 dungeons out of 40**, because compact placement gives most leaves a second connection. ⚠ It then fires **one dungeon in two** (René, 2026-08-27): an eligible leaf always exists, so without a draw it landed in 40/40 and « there is always a hidden passage » would have become a rule players learn — and systematic sweeping with it. ⚠ The rate is not fixed but a **pity counter** carried by the group (`groupes.chance_passage_secret`, written by `DemarreurQuete` on every quest start): **50 %** base, **+10 points** per map that came up dry, back to **50** as soon as one is placed. A pure 50 % draw can leave a whole campaign without a single passage, and such a streak does not read as chance — the party concludes the feature does not exist and stops searching. The worst case is bounded by construction (50→60→70→80→90→100, so never more than five dry maps); measured over 300 maps: 57 % carry one, longest dry streak 4. ⚠ The draw is taken **before** the edge is chosen and consumes a PRNG step **in both branches**: drawing only on the secretising path would make the number sequence diverge per branch, and two dungeons of the same seed would stop being identical. ⚠ The counter lives in a **column, never in cache** — losing it would silently reset the campaign to 50 %, which is exactly what it exists to prevent; and `assembler()` returns `passage_secret` because the caller **cannot** deduce it from the doors (a supplementary link is `secrete` too, and hides nothing). The old invariant « never dependent on a secret door » is **removed** from `CouloirsTest`: its justification (« a failed search would strand the group ») is obsolete since « Fouiller la zone » is offered **every turn with no limit** and `battre_en_retraite` (2026-08-21) has **no condition**. ⚠ Consequence to state, not hide: `donjon_nettoye` counts active monsters **revealed or not**, so an undiscovered room keeps `quitter_donjon` closed — the way out is the retreat vote, and a quest can now be lost for not having searched.

⚠ **Monster conditions finally EXPIRE** — `habillage.conditions[$cle]` carries the remaining turns instead of `true` (`true` still reads as "no timer", so in-flight data survives and every `! empty()` reader is untouched), and `MoteurSorts::decrementerDureesMonstres()` runs beside `decrementerDurees()`. Two storages, two methods: heroes have a `duree` column SQL can decrement, monsters have JSON that must be loaded, mutated and rewritten. Until then `terrifie`, `ralenti` and `paralyse` were **permanent** — `retirerConditionMonstre()` was only ever called for `endormi`, `saute_tour` and `enfume`, while `jouerMonstre()`'s comment claimed `decrementerDurees()` retired paralysis. It never did: a paralysed monster never played again. ⚠ `terrifie` stays permanent for want of a source (`Apeuré` carries `duree_defaut = 0`, i.e. "no counter", and Terreur declares no integer duration) — the same unresolved debt the hero side already carries, documented rather than invented.

**Dread spells now obey the players' own rules** (2026-09-01). The GM's magic was decided by `MoteurDread::choisirSort()` on a target list that was simply *every standing hero in the quest*: no line of sight, no range, no room. A boss struck a hero on the far side of the dungeon, through walls, inside a room never opened — the exact inverse of the rule the engine enforces on heroes ("line of sight required for EVERY spell"). `ciblesEnVue()` now filters through `FabriqueGrille::pour()` with `figuresBloquent: true`, the **same** call `MoteurSorts::filtrerLigneDeVue()` makes: one rule, both sides, or the MJ is playing a different game. ⚠ **Fuite is the exception** and keeps the full list — fleeing the only heroes you can *see* would be jumping into the arms of the one a wall was hiding; Charge likewise needs a path, not a sightline.

⚠ **`sorts_dread.palier` had no reader at all.** Doc 09 §4 states it as a *minimum* tier ("les sous-boss lancent déjà les sorts mineurs, le boss final ajoute les sorts vilains") and nothing enforced it: a sub-boss could Command, Summon and Flee. `sortsDisponibles()` gates on it, which is also what makes a **named archetype scale with the figure that carries it** — the Chamane Gobelin (sous-boss) draws Frayeur/Sommeil/Trait de Chaos from `chaman_orque`, a boss-rank shaman would also get Commandement, and `config/archetypes_lanceurs.php` stays declared *complete*.

⚠ **Two priorities decided on facts they never checked.** Tempête de feu was ranked first on the count of heroes *standing in the quest* while it only ever burns the caster's cell + 4 orthogonals — so it was chosen, journalled and spent on a zone holding nobody; `casesZone()`/`ciblesDansZone()` are now the single point of passage for both the choice and the resolution. And the control branch tested its three spells against **one** hero, the globally weakest Mind: if he already carried the condition the boss gave up on control entirely, though a companion beside him was perfectly sleepable. `cibleControle()` is now shared by `choisirSort()` and `sortDreadControle()` — the same recurring lesson as `Salles::indexDe()`: two copies of a rule too simple to notice drifting. Trait de Chaos also picked `$cibles->first()` (id order — the group's founder, all campaign long) where its own comment promised "le plus proche / le plus faible"; it now sorts on distance then HP.

⚠ **The `invocation` CAPACITY had no reader either** — the Seigneur and the Liche declared it and only the *spell* ever summoned. It is wired on the `charge` seam, costs **no** Dread usage (it is a capacity, not a spell), **shares** the spell's once-per-encounter lock so a monster carrying both summons once, and never fires **in contact**: a boss ringed by two heroes calling for reinforcements instead of striking is a gift, not a threat (same arbitration `pondre()` already makes for Spawn). `aCapacite()` reads **keys as well as values**, since `monstres.capacites` is a list for bare capacities and a map for parameterised ones (`['spawn' => ['creature' => …]]`) — reading values alone made every parameterised capacity invisible to it, the trap `pondre()` was already working around with its own `data_get()`.

⚠ **A live quest immediately found one more, and it was mine**: Trait de Chaos was sorted with `->sortBy([$closureA, $closureB])`, and Laravel's array form treats a callable as a **comparator** called `$f($a, $b)`, not as a key extractor — a one-argument closure therefore returned *the distance of `$a`* as the comparison result, and the boss struck the hero it was furthest from. It never errored. One closure returning a couple, and a test that only proves anything when the **nearer** hero comes first in the collection: staged the other way round, the vacuous version passed on the broken code too.

⚠ **The same `sortBy` had a TWIN, and grepping for the pattern found it**: `ResolveurTour::tirerSiCibleEnVue()` chose a ranged monster's target the same way — so the archer took the **robust** hero while a companion stood at 1 PV, the exact inverse of the comment above it ("PV de Body les plus faibles (achever), puis la plus proche"). One bug class, two sites: `sortBy([$f, $g])` is never a multi-key sort. On **two** candidates the buggy form returns the SECOND, whichever it is — so the locking test only proves something with the hero to finish off **first** in the collection, and it asserts that ordering rather than trusting it.

⚠ **The usage counters were in `Cache::forever`, and the consolidated rule forbids it.** A lost key returns 0, so the boss silently stops casting for the rest of the quest — undiagnosable at the table. They are columns now (`usages_dread`, `invocation_dread_utilisee`, `fuite_dread_utilisee`), which also puts them **in the snapshot**: a `/reprise` no longer hands the boss back the spells it had already spent. `brule` and `degat_differe` were missing from that snapshot for the same reason and went in with them — a restore used to put out the troll's burn. And `MoteurDread` kept **two occupancy loops of its own** (`grilleQuete()`, `casesLibresAdjacentes()`) that ignored furniture: a boss charged through a bookcase, Fuite teleported it into a table, and a summoned skeleton could land on a table or on a fallen hero. Both delegate to `FabriqueGrille::pour()`, the engine's single furniture loop.

⚠ **The hero side carried the mirror hole** (2026-09-02). `MoteurSorts` marked Concentration used in `Cache::forever` — durable per-quest state in cache, the same forbidden pattern, and *by construction* out of reach of the snapshot. It needed **no new column**: the three nodes carrying the mechanic (Concentration/Rappel/Communion) already declare `frequence: une_fois_par_quete`, so `Talents::disponible()`/`consommer()` and `etat_personnage_quete.capacites_utilisees` were the counter all along — it simply wasn't used here. ⚠ But moving it exposed the real defect: `Sauvegarde` serialized **only 7 keys** of a hero's quest state (position, slots, `tombe`), so a `/reprise` or a "Recommencer la quête" **handed back every once-per-quest capacity already spent**, wiped the spawnling tokens hooked onto the hero and refunded the first-blow defence die. `capacites_utilisees`, `styles_epuises`, `garde_tenace_utilisee` and `jetons_rejeton` now ride in both directions. The per-**turn** counters deliberately do not: the snapshot is taken at a round opening, exactly where they have just been reset. Nor does `reaction_en_attente` — a suspended round takes no snapshot, and resurrecting a stale offer would re-ask a question already answered. The `??` defaults on restore are not decorative: a snapshot taken before this date carries none of the four keys, and a campaign in flight must still resume.

**Movement is a RACIAL floor plus an agility trait** (`classes_heros.race`, René's call 2026-08-13). Four races — `humain` · `nain` · `elfe` · `halfling` — and a base of **nain 3 · halfling 3 · humain 4 · elfe 5**, **+1** where the class card sells the figure as agile (rogue, moine, berserker, explorateur). Outside the Warlock (halfling) and the Explorateur (dwarf), every extension class is human. ⚠ The grid is **entirely ours**: the cards give "2 red dice" with no base at all, so there is nothing to source here — only a consistency to hold, and it was not held. The **Explorateur**, a dwarf, walked at 5 where the Nain walks at 3, i.e. faster than the Elf. Race had lived as a **comment** until then: nothing in the DB or on any screen said what a class was, so a player watching an Explorer fall behind a Rogue could not possibly guess why. It is now a column, `/api/guide` prints it beside the class, and `CapacitesInneesTest` **derives** each expected value from `race` instead of re-listing twelve numbers — hand-copied, the grid and the data drift apart at the next class added.

**Five classes cast spells, and the Elf has TWO paths** (`MoteurSorts::LANCEURS`, doc 01 §4bis, René's call 2026-08-11). Barde, Druide and Warlock joined magicien and elfe — their cards *are* spells, which is exactly why those three carry no innate card capacity. Each gets a **class repertoire** (`REPERTOIRES_CLASSE`, keyed on `sorts.element`: the column is reused rather than adding a table for three rows). The **Elf** chooses at creation between an elemental school and **3 spells** from the `elfique` repertoire (8 in catalogue, Mage of the Mirror). Both paths weigh the same — three spells either way — only the freedom of the pick changes. They never mix: both would give six spells, neither would leave a caster with no magic. `PUT /groupes/{id}/sorts-elfiques` re-chooses the repertoire (**hub only**), and is **refused** to an elf who took a school — a school is definitive, and its spells are what the tree unlocks. Saying nothing still takes the historic path (default school), which is what keeps old clients, seeders and test helpers working.

**Traverser la Pierre is a movement MODE, not a teleport — and it is cast on ANY hero in line of sight.** ⚠ Its card arrived on 2026-09-02 (René's transcription, doc 16 §3bis) and falsified our target: "This spell may be cast on any one hero in your line of sight, **including yourself**", where we carried `cible: soi` — a porting choice taken when doc 16 §3 still read "⚠ non trouvé" for this spell, and one that made it the only member of its own scroll list not to be `heros` (*Peau de Pierre*, same list, always was). Nothing else had to be wired, and that is what made the switch safe: `traverseRoche()` reads the buff **on its bearer**, and `ce_tour` expires at the end of **that bearer's** turn, not the caster's — so a buffed ally keeps the movement mode for their own turn. The card's "once per quest" **confirms** rule S5 rather than constraining it (every spell is once per quest via `personnage_sorts.disponible`) — no second grammar for what the pivot already says. Its "during their **next movement**" is ported as `ce_tour`: the two coincide in all three real cases (self-cast — acting without having moved keeps the full allowance —, an ally yet to play, an ally already played whose buff crosses the round), and the residual gap is stated rather than hidden: a bearer who ends a turn **without moving** loses it, where the card would keep it. Casting it buffs the target for the turn (`franchit_mur`, `duree: ce_tour`); `Grille::autoriserLaRoche()` then lets *that hero's* pathfinding cross rock **and closed doors** — figures and furniture still block, and line of sight is untouched (you don't see through walls). Ending the movement in rock makes the hero **fall** (`tombe`, 0 PV): our engine has no instant death, and being down *inside a wall* is fatal in practice since reaching them needs the same spell (René's call, 2026-08-06). Entering an unexplored room this way **reveals it, monsters included, without opening the door** — `decouvrirSalle()` already funnels through `revelerSalle()`, so the fourth reveal path costs nothing new. It used to be a 2-cell teleport over a single wall, riskless, needing a free exit square. The spell has **no** movement cost: charging the allowance would make it unusable, since the movement *is* the effect — which is why the `cout` keyword introduced for it was removed again rather than left without a user.

**Three artefacts became ACTIVABLE, and they needed no new mechanic** (2026-09-03) — *Poudre d'Invisibilité*, *Cape des Ombres*, *Sceptre de Télékinésie*. Each reunites on an **object** what already existed on **spells**: the dust and the cloak post a movement buff that `traverseRoche()` / `franchitFigures()` re-read from the source item — those readers have always accepted `potion:`-sourced buffs, which is what made the port possible at all — and the rod joins `saute_tour` (Tempête) to the Mind-break roll (Sommeil). ⚠ `MoteurSorts::tenterRupture()` is now **generic over the condition**; `tenterRuptureSommeil()` is a name for the historic use. **Five more artefacts, still without a new mechanic** (2026-09-03) — the `activable` seam laid for the first three turned out to carry them. *Longue épée de Fortune*: 3 dice + `attaque_diagonale` (both already read) and its once-per-quest reroll posts the **same buff the Potion de bataille posts** (`relance_des_attaque`), the charge expressing the cadence. *Lame Fantôme*: `ignore_defense_monstre` existed as a **talent**; `MoteurSorts::valeurBuff()` — the numeric twin of `aBuff()` — now lets a buff carry it too, read with a `max` and never a sum, since two sources adding up would hand out a negative defence. *Bâton du Magicien*: the only one needing data beyond the item — a **`arme_magicien` tag**, because the wizard carried only `arme_legere`, which three other classes have, so granting the staff through it would have opened it to everyone the card reserves it from. *Élixir de Vie*: `restaure_jauges_depart` already existed on a potion; "brings a dead hero back to life" is rendered as both gauges to max **plus standing the hero up**, our engine having no death — and it is the **only** artefact whose legal target is a hero who is *down*, hence `tombeAdmis` threading from the menu's target list to the resolver. *Bracelet de Guérison*: its second sentence — "if the wearer's Body Points are reduced to 0, use immediately" — **is** the emergency-heal reaction written for potions on 2026-08-13; `soinsDisponibles()` only knew `categorie === 'consommable'`, so worn charged pieces now join the same whitelist under their own `artefact:` key, and the resolution spends a **charge** instead of consuming a copy.

⚠ **What is left needs real new mechanics**, and the registry names each: forcing the *attacker* to reroll (Dawnshield), a die against Dread spells (Scales of Elethorn), intercepting **Mind** damage (Sky Orb — `MoteurDegats` only sees Body), a reroll conditioned on the **face** rolled (Raven's Talon), plus teleport, trap-jumping, spell reflection and monster mind-control. ⚠ And a standing caution when adding more weapon artefacts: the project already discarded seven invented blades because they only climbed the dice curve. Fortune's Longsword escapes the reproach — its reroll is a *power* — but the line is thin.

⚠ **Testing the rod in real play uncovered a defect far wider than the rod** (2026-09-03). `HabillerMonstres` loads its instances, calls the LLM — seconds to minutes — then writes `habillage` back **from the copy it loaded before the call**. But `habillage` is not only dressing: it carries the monsters' **conditions** (endormi, saute_tour, terrifié, paralysé, ralenti, enfumé), the troll's burn, deferred damage, and `repousse_par`. Everything the party wrote during that window was silently erased — no log line, nothing on screen, and impossible to attribute. It only fires in the first minute of a quest, which is why three campaigns and a thousand tests never saw it: **no worker runs concurrently in a test**. Found by using a Sceptre de Télékinésie right after a quest start and watching `saute_tour` vanish; located by bisection after the menu, the boss and the second action had each been cleared by experiment. The fix is one `refresh()` before the merge. ⚠ Its regression test makes the race **deterministic** by posting the condition from inside the `Http::fake` **callback** — that callback runs exactly in the offending window, which is the only way to reproduce a concurrency defect without concurrency; it is verified to fail with the `refresh()` removed.

**The 12 SPELL CARDS are sourced too** (René's photos, 2026-09-02 — four PDFs in the project Drive, transcribed in `reference/16_armurerie.md` §3bis). Doc 16 §3 had carried "⚠ non trouvé" for 8 of the 12 spells since day one: the LR booklet shows one example card per element, the rest live only on cardboard. First finding, and it was not a given: **our 12 spells and their 4 elements match the cards one for one** — nothing to recut. Four were already exact (*Rock Skin*, *Heal Body*, *Water of Healing*, *Genie*), and the cards **settle §10's doubt about the two healing spells**: there really are two, in two different elements, with the same effect — our catalogue was right where we suspected ourselves of duplicating.

⚠ **Three spells were wrong, each in a different way.** *Courage* was missing **half its card** — "+2 dice on the next attack" was there, "the spell is broken the moment a monster is no longer in the hero's line of sight" was not, so the buff outlived the fight and waited for the next one; the keyword and its reader already existed (`plus_de_monstre_en_vue`), so `effet.duree` now accepts a **list** of triggers, first one wins (`DureeEffet::correspond()` is the single comparison point — it was `===` on two sites, where a composite duration would have been silently ignored and the buff would have expired **never**). *Voile de Brume* was **a different spell entirely**: we applied `inattaquable` (untargetable for a whole round) where the card says "move unseen **through spaces occupied by monsters**" — word for word the Rogue's *Mobilité de combat*, whose `franchit_figures` mechanic was already written; "unseen" is the colour of the passage, not an immunity, exactly as read on the Rogue's card. *Tempête* carried a `jet_mind` **the card does not have**, which made it weakest against precisely what it exists to slow down — a high-Mind boss; hence `resistance: aucune`, a word that had to be written because the key's ABSENCE falls back to `jet_mind` and therefore cannot say "no roll".

⚠ **A pre-existing defect fell out of the third fix**: with figures erased from the grid, nothing stopped a hero from **ending** their move on an occupied square — two figures stacked. The Rogue's talent had carried that hole since it was written; the smoke bomb held the same interdiction for its own account ("on traverse la fumée, on ne s'y arrête pas"), and it now holds for both.

⚠ **Two more were ported the same day, and these change balance** (René: "il faut respecter les pouvoirs originaux"). **Boule de Feu / Trait de Feu** now inflict a **FIXED** amount (2, resp. 1) that the *target* reduces by rolling that many **raw d6** — each 5 or 6 cancels a point (`resistance: des_rouges` + `des_resistance`, `defense_applicable: false` since the red dice **replace** the parry). We rolled combat dice with a normal defence: same range, different odds, and the randomness on the wrong side — it is the target who resists, not the caster who aims. ⚠ The boss's **Résistance magique** (+2 defence dice against spells) had no defence roll left to live in, so it becomes that many **extra red dice**; doing nothing would have silently switched the capacity off against the only two fire spells in the game. ⚠ Stated consequence: a damage talent adds **before** the reduction, so the dice can eat it — but they are fixed in number, so two dice cancel at most 2 of 3 and the talent now *guarantees* the last point; "fully parried" no longer exists once a bonus is in play. **Sommeil** always lands, and it is its *continuation* that is contested: the monster tries to break free **at once**, then **at the start of each of its turns**, rolling 1 d6 per Mind Point — a single **6** wakes it (`resistance: rupture_6_par_mind`). Both halves had been wrong: a single `jet_mind` at cast could make the spell fail outright, and once asleep a monster **never woke on its own** — only by being attacked. ⚠ It rolls at the *start* of its turn and plays that turn if it wakes: a sleeper that wakes should not also lose the turn it just won back. ⚠ And a sleeper **no longer parries** (René, same day: "après tout, il dort"): "cannot **defend itself**" is applied in `InstanceMonstre::apresConditions()`, on the very line of *Paralysé* — whose card carries the identical sentence — rather than at the three call sites, so hero blow, spell and ally attack all get it through `defenseEffective()`. The ordering holds by itself: the wake-up is posted *after* resolution, so the blow lands on a defenceless sleeper and then wakes it. Nothing on that card is left unported.

**Spells carry three more keyword vocabularies** (`App\Engine\MotsClesSort`, same reference doc): `cible` (`soi` · `heros` · `monstre` · `monstres_zone`) and `resistance` (`jet_mind`), plus the booleans `defense_applicable`, `saute_tour` and `ouvre_porte`. All are now **read**, not merely described. Three notes that bite. **Line of sight is required for EVERY spell**, not just offensive ones — "nécessaire pour lancer un sort ou observer une cible" (LR p. 14, `reference/16_armurerie.md` §6.4); the filter used to run only on the damage/mental branch, so a hero could be healed or buffed **through walls, across the whole dungeon, inside a room never explored**. The caster always sees themselves, so they stay targetable — "may be cast on any one hero, **including yourself**" (Heal Body, LR p. 8), which is also why `heros_ou_soi` was removed: it returned exactly the same list as `heros` and covered no rule at all. For a **damage or mental** spell `cible` states the intent but does **not** restrict — friendly fire is deliberate (doc 02 §5, S3), so the legal list holds monsters *and* heroes in line of sight; and `cout: deplacement_du_tour` had no reader at all, so `franchirMur()` walked the hero through the wall and left their whole allowance intact — Traverser la Pierre was **free** despite its own docblock saying it "vaut son déplacement". An unknown `resistance` now **422s loudly** rather than silently resolving with the wrong rule. `MotsClesSort::NON_IMPLEMENTES` lists words a catalog may carry that the engine does **not** apply (`monstres_zone`, `invocation_ephemere`) — **no spell uses either any more**, and a test forbids it. Checking them against the sourced booklets showed they were never debts but **data errors**: the official text is "**un monstre choisi** passe son prochain tour" (Tempest, Kellar's Keep p. 15 — never an area spell), and Genie is "opens a door of your choice **or** attacks with 5 combat dice" — no summon at all. Both were fixed at the source like `attaque_second_rang` before them. **Tempête now makes the monster skip its whole turn** (`saute_tour`), where the old `empeche_attaque` blocked only the attack and let it close the distance — the spell merely delayed by one turn a blow it then landed in contact.

**The stall drops what nobody in the party could use** (René's call 2026-08-18 — the same rule as furniture loot). Three potions are barbarian-only and two elf-only; a party with neither is no longer offered them. ⚠ This does **not** close off buying for a companion: the filter uses the **union** of every active member's masteries (`Equipement::tagsAccessiblesAux()`), so a barbarian potion stays on the shelf as long as the party has a barbarian, whoever pays — the purse is shared and gifting exists. What disappears is only what no hero of this party could ever drink or wear, and the "non maîtrisé" badge still tells *this* player what *their* hero cannot equip. Empty mastery list means no restriction (fail open).

**A new campaign starts with 0 gold — on purpose** (René's call, 2026-08-05). Heroes begin with their class weapon and nothing else; the first market phase of a campaign therefore has an empty purse, nothing is affordable and all three mercenaries read "Or insuffisant". That is the intended shape, as on the board: the first loot is earned in the dungeon, and the market only becomes meaningful from quest 2 on. Do **not** "fix" it by granting a starting purse.

**Giving items between heroes.** `POST /groupes/{id}/dons` (`app/Partie/DonObjet.php`) — **hub only**, like equip/unequip and the Forge. A player gives from **their own** heroes to **any active hero** of the group, including another player's; the receiver confirms nothing but their bag capacity is enforced, while the **giver** may be over capacity (shedding an item is how you regularise a bag saturated by quest loot). An equipped piece must be unequipped first. Consumables transfer by stack and **merge**; everything else **moves the inventory row** rather than recreating it — recreating would silently drop the row's Forge `ameliorations`. Artefacts circulate too: a `unique` weapon belongs to the group, and giving is not selling.

**The AI BUILDS the quest, it no longer PLAYS it** (`quetes.recits`, `App\Agent\Skills\RecitsQuete`, `App\Partie\Narration\TempsFort`, René's call 2026-08-18). A quest used to cost **~145 LLM calls**; it costs **2**. Three findings drove it. `ChoixController` dispatched `GenererMenu` **for all four heroes on every action**, while `GET /menu` already refuses to serve a menu out of turn (the `estSonTour` guard, 2026-08-13) — **three enriched menus in four were generated and thrown away**, and `MenuChoix` alone was ~75 % of the campaign's calls. `ContexteAssembleur` shipped **15 journal events with their raw payloads** in `JSON_PRETTY_PRINT` — 9-18 KB of prompt per call. And every AI narration was synthesized to speech at runtime, its `sha1` cache never hitting because the text was unique, against a **100/day** TTS quota. So: **all narrative text is now pre-generated once, at quest start**, into `quetes.recits` (`{salles: {id: {texte, ambiance}}, temps_forts: {cle: {ambiance, variantes[]}}}`), and the menu is **fixed** — `MenuMoteur` alone, no AI dressing. In quest, **zero LLM calls, zero runtime TTS, zero wait**; the point is as much speed as cost.

⚠ **The AI only writes what is PROPER TO THIS QUEST** (René's refinement, 2026-08-18) — the room descriptions and **three** beats: `fouille_artefact` (the dungeon's unique weapon), `quete_demarree`, `victoire_quete`. **Everything else is generic**, and that is a reasoning, not a saving: a search outcome is a **draw**. The AI cannot know whether the hero will turn up gold, a potion or a wandering monster, so writing all five outcomes to measure says nothing a fixed table doesn't — for ~5 500 output tokens and two to three minutes per quest. It first shipped generating all 24 keys; dropping 21 of them took the quest build from 3 LLM calls to **2** and cut the wait to seconds. Nothing had to be unwired: `pourQuete()` already falls through to the config for any key the pack lacks, so the fix was to stop producing them. `App\Partie\Narration\TempsFort` is the closed vocabulary — its keys, their legal variables **per key**, and `GENERES_PAR_QUETE`. Three producers must agree on it (skill, `config/narration.php`, `ChoixController::cleTempsFort()`), and it exists because they *didn't*: the ten search keys were generated and routed nowhere, so finding 25 gold narrated as "one more room". `TempsFortsLusTest` and `RepliNarrationCompletTest` now enforce both directions.

`BibliothequeNarration::pourQuete()` / `::salle()` are the single runtime entry: quest pack → `config/narration.php` → `null`. ⚠ **The scripted fallback is the NOMINAL case**, not a safety net: it carries 21 of the 24 beats outright, plays during the first seconds of *every* quest (the pack is written by an async job), and runs an *entire* campaign with no API key. Variables are `{heros}` `{monstre}` `{objet}` `{or}`; `attaque_touche` carries none, since the striker may be hero or monster. An unsubstituted variable is **left in the text on purpose** — a mangled sentence goes unnoticed, `{monstre}` does not. `recits` rides in the snapshot and is **pinned** on restore like `salle_artefact`: a "Recommencer la quête" must not re-buy text already paid for.

**A room carries TWO texts, and the voice picks** (René's call, 2026-08-18). `texte` is frozen and variable-free — that is what lets its narrator audio be pre-recorded, keyed by `sha1`; `entree` is one line naming the arriving hero via `{heros}`. `salle()` decides on a **fact**, not a setting: if the audio file exists, serve the frozen text alone (slipping a name in would desynchronise it from its own soundtrack — you would hear one sentence and read another); if it doesn't, the table reads aloud anyway, so naming the hero costs nothing and `entree.' '.texte` is served. Nothing to re-wire when the TTS quota runs dry mid-campaign: rooms already recorded keep the real voice, later ones name the hero.

`GenererRecitsQuete` (one skill, `RecitsQuete`) hangs off **all three** exits of `HabillerMonstres` (a monsterless dungeon still has rooms to describe) — room texts must cite the **dressed** monster names. ⚠ **Only room descriptions get the narrator's real voice** (`GenererVoixQuete`): a templated line exists only once substituted, so its hash could never hit the cache — the table reads those in Web Speech. That drops TTS from ~38 requests per quest to ~10, and makes adding beat variants free. Per-skill output caps live in `services.llm.max_tokens_par_skill`, keyed on `nomOutil()` and read by `Skill::plafondSortie()` (Anthropic `max_tokens`, Gemini `generationConfig.maxOutputTokens` — which was sent **no** `generationConfig` at all before). ⚠ Under-sizing a cap does not shorten the output, it **truncates** it, and a truncated `tool_use` is invalid JSON: the whole pack silently falls back. ⚠ Two infra defects surfaced only on the real stack, never in tests: the job outran the worker's `--timeout=120` and, writing both halves at the end, **discarded work a `try/catch` cannot protect** (a timeout kills the process); and `queue.database.retry_after` (90 s) sat **below** the worker timeout, so the file re-reserved a running job and **billed the same call twice**, leaving nothing but a `FAIL` in the log. **Deleted with this**: `MenuChoix`, `Narration`, `GenererNarration`, plus `DetailQuete`/`GenererDetailQuete`, dead since 2026-07-27.

**The moments that matter are spoken again** (campagne jouée du 2026-08-20, 4 quêtes, 4 371 événements). The pre-generation switch held its promise — 9 LLM calls for the whole campaign, 2 per quest, **0 during play** — but the play-test showed the *récit* had lost its peaks on the way. Three defects, each confirmed several times:

⚠ **`terminerQuete()` is the ONLY exit of a quest** — vote and objective alike — which is why `ChoixController::cleTempsFort()` never reached its own `victoire_quete` branch: no quest ending traverses that controller. Four consecutive victories, the final boss included, closed in total silence while each pack carried a bought-and-paid-for victory text. The narration now fires there, and ⚠ **before** the `phase => hub` switch: `diffuserRecit()` journals, and `Evenement.quete_id` resolves from the group's *current* quest — narrate after, and the victory attaches to nothing.

⚠ **Combat silence was a LATENCY compromise, and the latency is gone.** The comment said it outright: "menu moteur immédiat + barks […] SANS attendre le LLM". There is no LLM. What remains is a pacing choice — narrating every parry would make combat chatty and raise the B1 lock on each exchange — so the silence stands, with one exception: `ChoixController::momentFort()` lets a **boss or sous-boss death** through (`boss_vaincu`, the only combat beat that names its target). It resolves `tier` from the **catalogue**, never the displayed name — AI dressing renames creatures, and "Le Noyé de Gorrim" says nothing of its rank — and reads `frappes[]` too, or a sweeping strike would mute the most spectacular kill in the game.

⚠ **A hero falling is observed on the COLUMN, never wired to callers.** `tombe => true` is written from **eight** places (ResolveurTour ×4, MoteurPieges, MoteurDread ×3); `EtatPersonnageQuete::booted()` watches the flip and delegates to `App\Partie\Narration\AnnonceurChute` — same reasoning `Personnage::booted()` already states for HP. Wire the eight and the ninth damage path ships mute. `heros_tombe` / `heros_releve` are therefore **not** reachable from `cleTempsFort()`, and `TempsFortsLusTest` documents that second route rather than pretending there is one.

**The quest opening finally gets its own text.** `quete_demarree` was broadcast by `DemarreurQuete` while the pack lands tens of seconds later, so `recits` was *always* empty at that instant and the beat fell to the generic variant every time; and the **start room's description was structurally unreachable** (room 0 is seeded as already-discovered, so `revelerSalle()` returns at once). The one moment meant to establish the dungeon was the only one receiving nothing the AI wrote for it. `GenererRecitsQuete` now broadcasts the opening — beat + room 0 — once the pack is written; the scripted ceremony still plays instantly, as the curtain-raiser. ⚠ And `HabillerMonstres` dispatches **récits before images** on all three exits (they share the `default` queue, so dispatch order *is* execution order): the pack used to wait behind two 70 s image jobs and land at t+4 min, letting the quest play four minutes on the generic fallback.

**Variant counts follow FREQUENCY, not uniformity.** The keys that fire on every die roll and every blow had **two** variants while rare keys had three — a leftover from when these lines were merely a net behind AI narration. Measured: 293 narrations for 94 distinct texts, the commonest read **eighteen times** in one quest. `reussite`/`echec`/`progression`/`attaque_*` now carry 8-12, searches and furniture 5-6, and `RepliNarrationCompletTest` enforces a **per-key floor**. ⚠ Adding variants is **free**: templated lines are never synthesized to speech (their text exists only once substituted, so the hash never hits) and live in config — zero tokens, zero TTS quota.

**The quest objective is visible at last** (`EtatGroupe.quete.objectif` / `objectif_libelle`, from `Quete::objectif()`). The engine had read `structure.objectif` since it became the real victory condition, but showed it to nobody: a party explored 8 rooms of 10 drifting 38 squares away from the boss it had to kill. An unknown objective renders nothing rather than inventing a brief — same caution as `objectifAccompli()`, which treats the unknown as accomplished.

**« Renforcé » covered three different things** and its own effect admitted it (`attaque_ou_defense_selon_source`). A player could not tell whether they hit harder or took less, nor when it expired — the durations differ. Split three ways: `Renforcé` (attack dice), `Protégé` (defence, plus *Ailes sombres* and *Image double*, both protective), `Intangible` (*Traverser la Pierre*, a movement mode that was never a reinforcement).

**Retreating is now possible — and it is the only way out of a losing fight** (`VoteGroupe::TYPE_RETRAITE`, René's call 2026-08-21). `quitter_donjon` only ever said "we're done, let's go home": it is offered solely once the objective is met or the dungeon emptied. A party that was *losing* could therefore neither win nor leave — seen in a real campaign with two heroes down, two fragile survivors and the boss standing: the only mechanical exit was to fall entirely. `battre_en_retraite` has **no condition at all**, and that is the point — retreating must stay possible at the worst moment, or it is not a retreat.

It opens **one vote with three outcomes** rather than two votes, because retreating only makes sense if you know where to: `recommencer` restores the quest's opening snapshot (`Sauvegarde::redemarrerQuete`), `arreter` closes the campaign (`ClotureCampagne::arreterImmediatement`) — both already existed, but only on the narrator's emergency panel. ⚠ **Relative majority, and ANY tie continues**, including a tie between the two destructive outcomes: they erase or end everyone's game, so a minority must never impose them. ⚠ **Everything is said before anything is done** — narration *and* journal precede the action, because `arreterImmediatement()` purges the campaign: narrate after and there is no group left to journal against (the victory has the same trap for a different reason). A failed retreat (no opening snapshot) is caught and the game simply continues. ⚠ Since it has no gate, `recommencer` doubles as an unlimited undo — that is the accepted cost of the choice, not an oversight.

**The quest opens on a full-screen card, and says what it is doing while it builds** (`OuvertureQuete.vue`, `App\Events\EtapePreparation`, René 2026-08-21). The scene illustration existed but only ever appeared as a **56 px thumbnail** in the top bar; and building a quest takes one to two minutes during which the table said *nothing* — the group waited in front of a mute dungeon with no way to tell progress from a freeze. One panel now covers both moments: the announced step while it builds (`habillage → scene → recits → voix → pret`, a segmented gauge rather than a percentage — step durations differ by an order of magnitude), then the scene image full-bleed with the opening text. ⚠ It closes on **end of reading**, the same signal that thaws the controllers (B1), never on a timer: cutting mid-sentence while the narrator speaks aloud would be worse than nothing. ⚠ `pret` is broadcast from a **`finally`** in the last job, which exits five different ways (no TTS key, setting off, quest gone, quota exhausted, normal end) — miss one and the table stays "loading" forever. The step is also **cached and exposed in `EtatGroupe.preparation`**, so a table opened or reloaded mid-sequence finds where things stand.

⚠ This is why `GenererImagesQuete` takes a `volet`: the **scene** is dispatched *before* the récits and the **boss portraits** after. Splitting it is a sequencing decision, not a tidying one — without it the opening card would never have its image on a first quest, which is the whole point of the card. The price is stated: the pack lands at ~2 min instead of ~1, so a little more generic fallback at the very start of a quest.

**A missing illustration now shows an SVG emblem, not a hole** (`PlaceholderController`, `GET /api/placeholder/{type}/{graine}`, René 2026-08-21). Playing without an AI key is a supported way to play, and Gemini credits can run dry mid-campaign — the screen simply rendered nothing, which reads as a bug. ⚠ It is **not a fake illustration**: a plain emblem per subject type (dungeon arch / hearth / horned skull), owned as a placeholder. SVG rather than PNG for three reasons — nothing written to disk (nothing to purge or regenerate), sharp at any size (the same asset serves a 56 px thumbnail and a 900 px opening card), and free to produce. The **seed** makes it stable *and* distinct: two quests of one campaign differ in hue, a given quest always keeps its own, so the screen never looks like it failed to refresh. ⚠ The URL carries **no `.svg` extension** on purpose — nginx serves static files by extension (`location ~* \.(…|svg|…)$ { try_files $uri =404; }`) and would never hand off to PHP. It covers **every AI-generated image** — quest scene, hub, boss portrait, hero/class, item, trap, spell — with a distinct emblem per type. ⚠ The vignette sits at the **END of each fallback chain, never in the middle**: a hero portrait still resolves to its class illustration first, a boss to its archetype's catalogue image. A real picture, however generic, beats an emblem. ⚠ `urlDyn()` therefore keeps returning `null` — it is the *raw* accessor, and it is what makes those chains possible; only the public accessors are total. ⚠ And **no subject means no vignette**: `urlClasse(null)` stays `null`, because an emblem would claim "image missing" where no image was ever expected.

**Token telemetry** (`App\Agent\TraceurConsommation`, table `consommation_ia`, block in the Réglages panel). `StatutIA` only ever held the last call's state — no counter existed, so the cost was never measurable. The tracer records **every HTTP response**, not every `generer()`: that is the only way validation retries (`Skill::MAX_RETRIES`, up to 3 billed calls for one output) and the cross-provider failover (`ClientLLMAvecRepli`, which replays the whole call) become visible. `Skill::generer()` announces the context, so all skills are covered without touching a single job. ⚠ The `groupe_id` it reads is deposited by `ContexteAssembleur` **outside** the `groupe` section — `contexteEnTexte()` serializes only the sections a skill lists, so it never reaches a prompt (same precaution as `identifiant`, which the AI once reused as a villain's name). Best-effort throughout: a failed telemetry write must never fail an AI call.

**AI GM is wired and verified live.** With `ANTHROPIC_API_KEY` (model `claude-sonnet-4-6`) the GM produces real campaign skeletons, quest récits (rooms + beats) and monster dressing — **at quest build time only**, never during play (see above); `LLM_PROVIDER=gemini` (+`GEMINI_API_KEY`, `GEMINI_MODEL`) switches the whole GM text pipeline to Gemini via the shared `ClientLLM` interface. With `VOYAGE_API_KEY` (`voyage-3.5`, 1024-dim) the bible does real semantic RAG. The binding auto-selects `EmbeddingsVoyage` when the Voyage key is set, else `EmbeddingsNuls` (lexical, dev). **The game must stay playable without either key** — every AI job falls back (engine-built menus, scripted narration from `config/narration.php`, catalog monster names). Since 2026-08-18 that is not a degraded mode but a supported way to play: nothing in a quest needs the LLM. After changing `.env` keys, recreate the `app`/`queue`/`reverb` containers AND restart `web` (nginx caches the app upstream IP — a recreated `app` otherwise returns 502 until `web` restarts).

**Global settings panel ("Réglages").** Gear button on both narrator screens (`/narrateur` and the table) → `ParametresPanel.vue`, backed by `GET/PUT /api/parametres` (**PUBLIC**, like `/api/guide` — contract in `docs/contrat-api.md` §Paramètres globaux) and a singleton DB row (`parametres` table, `Parametre::actuel()`). Server-side settings override `.env` **live, with NO container recreation** (unlike `.env` edits above): the `ClientLLM` binding is `bind()` (not `singleton()`) and re-reads the row on every resolution, so a change applies to the *next* queue job. Covered: LLM provider + model per provider, RAG on/off (`ContexteAssembleur`), in-game TTS (dynamic narration + boss barks — the offline `narration:generer`/`barks:generer` commands are NOT gated), narrator Gemini voice (honored by `narration:generer` too; pre-generated lines keep the old voice until manually regenerated), runtime image jobs on/off (`images:generer` NOT gated), and the 5 `config/jeu.php` encounter-balance knobs (apply to the *next* quest started). `ClientLLMAvecRepli` decorates the client with **runtime cross-provider failover** (primary call fails → one retry on the other keyed provider → else the skills' hard-coded fallback) and records `StatutIA` in the shared database cache — the panel banner shows nominal / amber failover / red "no model available". `POST /api/parametres/test` fires a real mini LLM call at ONE precise provider (never through the failover decorator, never touching `StatutIA`) with the form's model value — the panel's "Tester Anthropic/Gemini" buttons validate a key/model *before* saving. `POST /api/parametres/test-voix` synthesizes a fixed sample sentence with the form's narrator voice, cached per voice under `public/audio/narration/test/` (re-listening costs no TTS quota) — the "Écouter (Gemini)" button; "Écouter (navigateur)" plays the same sentence via local Web Speech (no server). Audio settings (voice & music volume/mute, speech rate, Web Speech voice picker — French voices first, chosen `voiceURI` persisted with auto-fallback —, and "narration via browser voice" — the NARRATOR's generated voice is replaced by Web Speech for all narration, AI-generated and scripted alike; monster barks keep their audio files) are **per-device** (`localStorage`), never server-side; the muted `narrer()` path still fires `apres()` (B1 turn lock — never regress this).

**Victory is the gabarit's objective.** `Quete::objectifAccompli()` finally reads `structure.objectif`, which no reader had ever touched: `vaincre_sous_boss` / `vaincre_boss_final` mean the instance of that `tier` is down, `atteindre_et_recuperer` means the deepest room's chest has been searched. An **unknown objective counts as accomplished** — data we cannot interpret must never lock a group inside its dungeon. `quitter_donjon` needs the objective **or**, as an anti-softlock fallback, a fully cleared dungeon (better to go home empty-handed than be trapped).

**Every secret door has a chest behind it** (`quetes.salles_coffre`): finding a hidden passage used to buy only a shortcut. The room *behind* the door — the deeper of the junction's two — holds a chest, never the start room. A chest costs **no deck card**; the deepest room's yields the **unique weapon**, the others gold or a potion. Progression earns the artefact; a shortcut earns loot.

**A quest no longer ends by itself.** Killing the last monster used to close the quest on the spot — so a group that finished off the final guard lost everything it had not yet searched, artefact chest and secret doors included, while **nothing ever forced them to explore** (victory is a clear-out; the gabarit's `objectif` is decorative and unchecked). The engine now only flags `donjon_nettoye`, `MenuMoteur` offers **`quitter_donjon`** while no active monster remains, and choosing it opens a **group vote** (`VoteGroupe::TYPE_SORTIE`) — strict majority, a tie means you stay and keep searching, so nobody's looting gets cut short by a hurried companion. `ResolveurTour::terminerQuete()` is public and called by the vote's resolution. The option is a **free interaction**, not an action, and it disappears if a search spawns a wandering monster. Tests that assert end-of-quest *effects* use the `acheverLaQuete()` helper in `tests/Pest.php`.

⚠ **A cleared dungeon must still OPEN THE NEXT ROUND** (`ResolveurTour::ouvrirNouveauTour()`, 2026-08-15). `phaseMonstres()` is the *only* method that resets `a_joue`, and **three** "no active monster" paths short-circuited it straight into `donjonNettoye()` — in `resoudre()`, in `apresActionHeros()`, in `jouerFinDeRound()`. So the last hero to simply *end their turn* after the final monster fell locked the whole group in an empty dungeon, permanently: `GenererMenu` produces nothing for a hero who has played, and `quitter_donjon` is only offered while they have not — the single window to close the quest shut on itself. No menu, no error, nothing to do from a phone. Found in live play by both players independently. The round now closes first and the `donjon_nettoye` flag is set *after*; the opening (slots reset, `prochain_tour` buffs expired, durations decremented, journal, snapshot) is extracted so the cleared path can call it without a monster phase to play. ⚠ Two votes have **no timeout and no default ballot** (6 h TTL): proposing is not voting, and the proposer must cast their own — the exit vote stalled a whole session at 1/2 because nothing said so.

⚠ **A market cart does not survive the departure** — and now says so. `/pret` **422s** a player whose cart is non-empty and unconfirmed (application is atomic, so no gold is ever debited, but the purchases vanished silently when the quest started and took the market phase with it — a player reasonably read that as theft). The refusal targets **that player only**, never the group: blocking departure for everyone would rebuild the exit-vote trap, where one distracted player locks the others in. Quest start closes the phase **explicitly** (`marche_ferme_par_quete` + broadcast) instead of letting it expire in six hours.

**Every door-opening path reveals the room.** Opening a door shows the room *and its monsters*, as on the board — but that rule used to live only in the explicit `ouvrir_porte` action. A **lever** or a **guardian's death** (`ouvrirParMonstresVaincus`) opened the door and left the room dark with dormant monsters: the way was open and there was nothing to see, while `FabriqueGrille` still counted those monsters as occupying their cells, so the controller offered moves the engine then refused. `ResolveurTour::revelerDerriere()` is now called from **all three** paths; `revelerSalle()` is idempotent, so calling twice is free. Fog also keeps walls **a hero is touching** truthful (`EtatGroupe::appliquerBrouillard`) — a masked wall used to come back as `b`, indistinguishable from unknown floor.

**Turn slots are exposed so the controller can grey out.** `EtatGroupe` hero entities carry `a_joue` / `a_deplace` / `a_agi`. The engine *omits* options whose slot is spent, but a displayed menu can predate the action — the player then clicked and got a 422. `ActionTab.creneauConsomme()` mirrors `ResolveurTour::creneauOption()`; keep the two in step, and keep the client tolerant of the flags being absent.

**`GET /menu` must answer the same question the resolver will.** It is a real UI path, not a debug route — the manette calls it on mount and on every reconnection — and it used to hand back a full, clickable menu to a hero whose turn it was not (found in live play by **three** players independently, 2026-08-13): every action then bounced on a 422 "Ce n'est pas le tour de ce héros". Reload your phone while someone else plays and you inherited a dead menu. The guard is `estSonTour()` — **initiative order**, not merely "has not played yet" — plus `! a_joue` and `! tombe`. ⚠ It has to cover the menu **already in cache**, which the first fix missed: a menu cached before its hero fell stayed served until *consumed*, and a downed hero consumes nothing, so a player sat three turns on a clickable "Attaquer" that answered "Ce héros est tombé" every time (2026-08-14). Stale, the menu is **forgotten**, not just hidden. Same anti-pattern the project hunts everywhere else: the menu must never offer what the resolver will refuse.

**No player-facing image generation.** Hero portraits on demand were removed (route, controller, job, roster button). `BibliothequeImages::urlHeros()` stays: already-generated portraits still display, otherwise the class illustration. Catalogue (`images:generer`) and scene images (hub/quest) are narrator-side and unaffected.

**The "MJ réfléchit" lock must always self-heal.** `MjReflechit` freezes every controller until the **table** reports it finished reading the narration (`POST /table/lecture-terminee` — the B1 lock, deliberate: players don't act before the narrator has spoken). The server-side cache expires on its own (90 s), but **that expiry reaches no client**: `.groupe.etat` is only broadcast on a mutation, and nobody mutates while everyone believes they are frozen — a deadlock that stopped a whole playtest. `ManetteView` therefore force-thaws after 30 s **and re-reads `/etat`**, because thawing the buttons alone left the "MJ réfléchit" banner up and the turn never visibly returned. Never remove either half. ⚠ Since 2026-08-18 the lock covers only the table's **reading** time, not a generation — narration is resolved synchronously from the pre-generated pack. The B1 semantics are unchanged and deliberate; every site that raises it also lowers it when no récit is found.

**Narrator emergency menu.** A second button next to the gear icon (`.status-urgence`, table screen only — no group context on `/narrateur` yet) opens `UrgenceNarrateurPanel.vue`: two destructive actions, each behind an inline confirmation step (no separate modal). "Recommencer la quête actuelle" → `POST /api/groupes/{id}/quete/redemarrer` (`Sauvegarde::redemarrerQuete`) restores the current quest's `debut_quete` snapshot **at any time**, not just after a TPK — unlike `/reprise` it has no failure-state guard, since it's meant for "this is going very badly, reset it" mid-quest. "Arrêter la campagne" → `POST /api/groupes/{id}/cloture/urgence` (`ClotureCampagne::arreterImmediatement`) ends the campaign **immediately with no per-player confirmation ritual** (unlike the normal `/cloture` flow): it builds a phase with every confirmation pre-set to `true` and dispatches the same `CloturerCampagne` job as a normal closure — same gold split, `personnage_historique` entry, `.cloture.terminee` broadcast, full purge — just skipping the wait. Both routes are **member OR table** auth (same trait as `/reprise`), so the button works from the table's session-only login, and both are meant strictly for the table screen, not the manette.

**Audio (voix).** The table screen reads GM narration via the browser **Web Speech API** (no key) and plays **monster barks** on combat events (`attaque`/`touche`/`rate`/`mort`) broadcast via `BarkDiffuse` on `groupe.{id}`. Bark text lives in `config/barks.php` (voice profile per archetype + `{nom}`-templated boss lines); audio is **pre-generated offline** by `php artisan barks:generer` (and `GenererBarksBoss` per quest) using **Gemini TTS** (`GEMINI_API_KEY`, never called during play). `BanqueBarks` resolves text+url; **without the key or assets, the table speaks the bark text via Web Speech** — audio is pure ambiance, never mechanical. Generated WAVs under `public/audio/barks` are gitignored (regenerable).

**Narrator voice.** Scripted narrator lines live in `config/narration.php` (`lancement` ceremony — broadcast immediately by `DemarreurQuete` when a quest starts — and `repli` variants for every beat — read by `BibliothequeNarration::pourQuete()` whenever the quest's pack lacks a key). `php artisan narration:generer` pre-generates a **dedicated narrator voice** (Gemini, profile `narration.voix`) into `public/audio/narration/{cle}/{i}.wav`; `GenererVoixQuete` does the same, per quest, for the pack's **room descriptions only**, cached by `sha1(texte)` under `public/audio/narration/dyn/`. `NarrationDiffusee` carries an optional `url`; the table plays it, else Web Speech reads the text. `BibliothequeNarration` resolves all of this. ⚠ **Gemini TTS quota:** the preview model `gemini-2.5-flash-tts` caps at **100 requests/day even with billing enabled** — generation commands are resumable (skip existing); spread bank generation across days or use Google Cloud TTS for higher limits. Runtime synthesis is gone since 2026-08-18, which is what took a quest from ~38 requests to ~10.

**Background music.** `EtatGroupe` exposes `groupe.ambiance` (`hub`/`exploration`/`combat`/`boss`, derived from active monsters/phase); the table (`useAmbiance`) crossfades the matching loop from `public/audio/ambiance/{scene}.{ogg|mp3|wav}` — silent if absent, unlocked by the same gesture as the voice. Loops are **generated by Google's music model Lyria RealTime** (NOT TTS — Gemini TTS can't make music) via `audio-tools/lyria-ambiance.mjs` (Node + `@google/genai`, streams 48 kHz PCM → WAV). See `audio-tools/README.md` for all audio-generation recipes. All `public/audio/**` is gitignored (regenerable).

## Commands

```bash
./setup.sh                            # interactive install: writes .env, builds, starts, migrates + seeds
docker compose --profile dev up -d    # dev mode (adds phpMyAdmin on 127.0.0.1:8081 + Vite hot reload on 5173)
docker compose up -d                  # "prod" LAN mode
docker compose exec app php artisan   # any artisan command (migrate, test, etc.)
docker compose logs -f app queue      # follow the app and AI jobs
docker compose restart queue queue-jeu   # MANDATORY after any PHP change (see below)
```

**Restart the queue workers after every PHP change.** `app` reads the bind-mounted
code per request, but `queue`/`queue-jeu` are long-running `queue:work` daemons that
load classes **once at boot** — after a migration + code change they keep running the
*old* code against the *new* schema. That is not theoretical: it froze a whole
playtest (2026-08-05) when `GenererMenu` died on the renamed `mobilier.bloquant`
column, so no menu ever reached the controllers and both players sat on "Le maître du
jeu prépare la suite…" for 20 minutes with no error anywhere. `GenererMenu::failed()`
now publishes a minimal "Terminer le tour" menu so a dead job can never freeze a group
again — but that is a safety net, not a substitute for restarting the workers.

PHP, Composer and Node are NOT installed on the host — everything runs through containers. When the compose stack isn't up, use throwaway containers (these are the proven incantations):

```bash
# composer / artisan / Pest against sqlite (database/database.sqlite):
docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -v "$PWD:/app" -w /app \
  -e DB_CONNECTION=sqlite -e DB_DATABASE=/app/database/database.sqlite \
  composer:2 <composer …|php artisan …|./vendor/bin/pest …>
# front build:
docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -v "$PWD:/app" -w /app \
  node:20-alpine sh -c "npm install && npm run build"
```

Tests are **Pest** (`./vendor/bin/pest`; engine suite under `tests/Unit/Engine`, run a single file by path). `composer.json` pins `platform.php` to 8.3 (the runtime image) — keep it when resolving deps.

**Visual/browser testing** (no Chrome on host — use the official Playwright image, which bundles Chromium + all system libs). With the stack up (`http://localhost`), screenshot key pages and inspect the PNGs:

```bash
docker run --rm --network host -v "$PWD:/work" -w /work \
  -e PLAYWRIGHT_BROWSERS_PATH=/ms-playwright -e PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 \
  mcr.microsoft.com/playwright:v1.48.0-jammy \
  bash -c 'npm i playwright@1.48.0 --no-save --no-audit --no-fund --silent && node browser-shots/shots.mjs'
```

**Every generated PNG needs its `.webp` twin — run `image-tools/webp.sh` after `images:generer`.** `BibliothequeImages::url()` serves the `.webp` when it exists and falls back to the PNG otherwise, so a missing twin breaks nothing and simply makes the screen **thirty times heavier** — the market went to ~46 MB on a phone before the twins were made (measured 2026-08-22; the mechanism itself dates from René's 2026-08-07 report, "la tablette prend vraiment du temps à charger"). 1024×1024 PNGs weigh ~1.3 MB, their webp ~50 KB. PHP here has **neither gd nor imagick**, so this cannot be an artisan command — it runs in a throwaway container like the audio tools, and ⚠ `apk add` needs root while the files must belong to the host, hence the `su-exec` dance in the script's header (a plain `-u $(id -u)` fails on "Unable to lock database"). The PNG stays the source and is never touched, so `--force` can replay a different quality.

**No demo mode.** There is no fake-data fallback anywhere in the SPA anymore — every screen shows its real loading/error state when the API is unreachable or a group code doesn't exist, on purpose, so bugs surface instead of being silently masked. Always test against the real stack (`docker compose up -d`, seeded). `browser-shots/shots.mjs` registers a throwaway player, creates a character + group via the real API, then shoots accueil, /narrateur, /joueur, the manette, and the table screen — all real, no `/table/DEMO`-style routes. PNGs (gitignored) land in `browser-shots/` — read them to check rendering. Pin the `playwright` npm version to the image tag. Watch for **CSS class collisions**: many SFC `<style>` blocks are global (not `scoped`), so generic class names like `.joueur` leak across views — prefix view-specific modifiers.

**Cleaning up after a test session — a command, deliberately not a `est_test` flag.** `php artisan partie:purger` (inventory by default, `--supprimer` to act, `--tout` to also drop accounts and IA telemetry) resets the DB to "no game played", catalogues and settings untouched; `browser-shots/campagne/nettoyer.sh` is the targeted counterpart `preparer.sh` never had. ⚠ Both go through **`ClotureCampagne::purger()`** rather than deleting rows: that service also takes the phase caches, the group's **Qdrant bible** and its **illustrations** — a plain `DELETE` leaves all three behind. A flag was considered and refused (René, 2026-08-23): the harness plays the **real routes** on purpose, so a client-set flag is one tests forget, and a server-set one needs a test-only code path — exactly what "No demo mode" forbids. It would become another decorative key, and it would have prevented nothing: the harness campaigns were already purgeable, **nothing purged them**. The gap was a step, not an identity. ⚠ `BibleQdrant::groupesIndexes()` exists for the same reason as the orphan image sweep: group ids recycle, and a bible left behind by a failed best-effort purge would be **inherited** by a future campaign — the RAG feeding the AI a stranger's promises, silently. Measured 2026-08-23: 185 points across 46 vanished groups.

**Playing a real campaign is a test method** (`browser-shots/campagne/`, README in the same folder). Sonnet agents each drive one hero over the **real** manette routes: `hq.sh <slot> etat|menu|moi|pret|choix|potion|reaction` (one cookie jar per player = one session), `vue.py` prints the board, `battement.sh` keeps the table heartbeat alive, `figurants.sh` passes the turns of heroes nobody is playing. Three campaigns found **ten** defects that 761 green tests did not: the menu served out of turn and to fallen heroes (above), Paralysé that forbade only spells, a zone spell asking for a target it ignores, a combat log conflating a miss with a parry, a Terreur spell that 422'd whenever its target *failed* the resistance roll, double journalling, a ghost spell in the live DB absent from the seeder, the guide dropping 15 spells, and the empty capacity description on the reaction sheet.

Two things it taught, both in the README. **A role does not test itself — prepare the situation.** The Knight's three reactions never fired across two whole campaigns because nothing ever arranged for a monster to strike a neighbour; they were finally validated by staging the board (and ⚠ `proposerDefi()` **excludes the searcher**, so a *neighbour* must draw the wandering-monster card). Same for the dwarf's traps — *Œil du mineur* is a purchasable tree node, not an innate, so a level-1 dwarf walks into pits, which is correct. **And an agent that stops freezes the group**: its hero never ends its turn, the round never closes, and nobody else can see why — give the agents no monitoring tools, and cover idle heroes with `figurants.sh`. The README also lists the three attributes that do **not** exist and return `null` in silence when you stage a scene by hand (`inventaire.equipe`, `quetes.fouilles_effectuees`, `Personnage::classeHeros`) — each one costs an hour of chasing a bug that isn't there.

## Architecture

Stack (design doc 11): modular **Laravel monolith** + **Vue SPA** clients + **Reverb** (WebSocket) + **MariaDB** (exact game state) + **Qdrant** (RAG "bible"), all on one docker-compose host. Anthropic or Gemini API for the LLM (`LLM_PROVIDER` default + live override via the Réglages panel; keys in `.env` only, never in images).

**Founding principle (enforced everywhere): the deterministic engine is authoritative on all mechanics; the AI only narrates and proposes.** Concretely, in `GenererMenu::fusionner()` the AI **never mints an option**: every entry of a menu comes from `MenuMoteur`, the AI only lends it a dressed `libelle`. It used to inject its own `dialogue`/`action`/`jet` options unchecked — which let it reuse a mechanical id the engine had just withdrawn (`fouiller_tresor` on an already-searched room: accepted by the controller, rejected deep in the resolver) and produced decorative options that failed silently because nothing resolved them. Flavour actions are to come back **anchored to elements the AI places on the map at creation time**, resolved by the engine the way levers already are.** Dice, HP, combat, skill checks are resolved in code. AI outputs are constrained by JSON schemas (structured outputs) and then validated by the engine against the catalogs — reject/retry on invalid. Players never type free text: the loop is *AI narrates → AI generates a contextual choice menu → engine resolves the chosen option*.

Laravel modules (all French naming, matching the design docs):
- **`app/Engine`** — pure PHP rule classes (dice, skill checks, combat, movement, mental spells), no HTTP/Eloquent. The authoritative core; dice roller is injectable and seedable (`LanceurDeterministe` for tests). Heavily Pest-tested — don't change behavior without updating `tests/Unit/Engine`.
- **`app/Agent`** — single GM agent: `AnthropicClient` (forced tool use), `Skills/` (one per task: SqueletteCampagne, DetailQuete, MenuChoix, Narration — each = JSON schema + prompt assembly + catalog validation with retry then hard-coded fallback), `Memoire/` (ContexteAssembleur, BibleQdrant with `group_id` payload filtering, `Embeddings` interface). Runs only in queue jobs (`app/Jobs`), never blocking the API.
- **`app/Partie`** — game-loop services orchestrating Engine + Models (quest start, map assembly from seeded tiles, encounter budget from group power score, turn resolution, scripted monsters).
- **`app/Models`** — French-named Eloquent models over the doc-12 schema; catalogs are seed-only reference data.

Turn flow: phone (Vue) sends a menu choice → API validates legality via engine → engine resolves deterministically, updates state + journal → job dispatched for next narration/menu → result broadcast via Reverb (group channel `groupe.{id}` for the host "table" screen, private per-player channels for each phone's menu).

Multiplayer model: roles are views, not devices — any browser can be **host** (shared table screen, narration/TTS) or **player** (controller).

Entry/session model (`docs/contrat-api.md` §Modèle de session): the **narrator/table** has no account — it opens a group by **code** (`POST /api/table`) and keeps a **heartbeat** (`POST /api/table/ping` ~every 15s → cache `table:active:{id}`, 30s TTL = "narrator active"). **Players** have accounts (register/login), a **roster** of characters (`/moi` → each character `disponible` or engaged with `groupe.narrateur_actif`), create a group **from a free character** (founder) or join by code. A quest starts when **all active members are marked ready** (`POST /groupes/{id}/pret`) **and** a narrator is active. Read routes (`/etat`, channels) accept a player member **or** the group's table session.

Data: catalogs (bestiary, items, spells, tiles, traps) are seeded reference data — the AI may reskin names/descriptions but never change effects. Full schema in `reference/12_schema_donnees.md`. A complete campaign = the `mariadb_data` **and** `qdrant_data` volumes; back up both together.

## Design documents (`reference/`, French — the source of truth for all game rules)

`00_synthese.md` is the index: per-domain key decisions (coded P1…, S1…, C1…, M1…, Q1…), cross-doc dependency map, open questions, and MVP vs Phase 2 scope. Docs 01–05 (characters, spells, combat, market, session) are fully decided; docs 06–10 (quests, memory, guardrails, bestiary, traps) have listed open questions — don't silently resolve those, surface them. All numeric values (stats, prices, difficulties) are explicitly starting proposals for playtesting. `reference/uploads/13_design_ui.md` and `reference/heroquest/` cover UI design.

**Docs 16–18 are a different kind of document: sourced extracts of the OFFICIAL Avalon Hill 2021 booklets**, downloaded from `instructions.hasbro.com` — 16 armoury/heroes/bestiary/rules, 17 furniture, 18 the thirteen expansion boxes. Every value cites its booklet and page; anything unverifiable carries `⚠ non trouvé` rather than a guess. **Never seed a value these docs don't source** — that rule is what keeps decorative keys from coming back. Three findings shape everything downstream: **prices and the 8 base monsters' stat table exist in no booklet** (they live on the equipment cards and the GM screen, cardboard components never digitised — René's photos are the only way in, and they arrived: monsters via the Sjeng deck, **prices via doc 16 §2.1bis**, 2026-08-14); the 2021 roster is Goblin/Orc/**Abomination**/**Dread Warrior**/Skeleton/Zombie/Mummy/Gargoyle, so our *Fimir* and *Chaos Warrior* are 1989 Milton Bradley names; and the expansions add only **4 confirmed playable classes** (Rogue, Monk, Bard, Explorer), **none with an official stat card**. Known deliberate divergences from the board: our movement is a per-class base + 1d6 where the board rolls 2 red dice with no base (René's decision, kept), and thrown weapons are lost where the board treats the dagger as a permanent ranged weapon.

## Security constraints (doc 11 §11–13)

- MariaDB, phpMyAdmin and Qdrant are never exposed outside the compose network (no published ports; phpMyAdmin binds 127.0.0.1 only).
- Simple auth is acceptable for LAN/VPN only; WAN exposure requires TLS proxy + hardened auth (VPN recommended instead).
