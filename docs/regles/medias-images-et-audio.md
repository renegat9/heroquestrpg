# Médias — illustrations, voix, ambiance

> Extrait de `CLAUDE.md` le 2026-09-06, **verbatim**. Ce sont les **règles en
> vigueur** — pas un document daté comme `docs/plan-*.md` / `docs/verdict-*.md`.
> Index : `CLAUDE.md` §« Règles établies ».

**A missing illustration now shows an SVG emblem, not a hole** (`PlaceholderController`, `GET /api/placeholder/{type}/{graine}`, René 2026-08-21). Playing without an AI key is a supported way to play, and Gemini credits can run dry mid-campaign — the screen simply rendered nothing, which reads as a bug. ⚠ It is **not a fake illustration**: a plain emblem per subject type (dungeon arch / hearth / horned skull), owned as a placeholder. SVG rather than PNG for three reasons — nothing written to disk (nothing to purge or regenerate), sharp at any size (the same asset serves a 56 px thumbnail and a 900 px opening card), and free to produce. The **seed** makes it stable *and* distinct: two quests of one campaign differ in hue, a given quest always keeps its own, so the screen never looks like it failed to refresh. ⚠ The URL carries **no `.svg` extension** on purpose — nginx serves static files by extension (`location ~* \.(…|svg|…)$ { try_files $uri =404; }`) and would never hand off to PHP. It covers **every AI-generated image** — quest scene, hub, boss portrait, hero/class, item, trap, spell — with a distinct emblem per type. ⚠ The vignette sits at the **END of each fallback chain, never in the middle**: a hero portrait still resolves to its class illustration first, a boss to its archetype's catalogue image. A real picture, however generic, beats an emblem. ⚠ `urlDyn()` therefore keeps returning `null` — it is the *raw* accessor, and it is what makes those chains possible; only the public accessors are total. ⚠ And **no subject means no vignette**: `urlClasse(null)` stays `null`, because an emblem would claim "image missing" where no image was ever expected.

**No player-facing image generation.** Hero portraits on demand were removed (route, controller, job, roster button). `BibliothequeImages::urlHeros()` stays: already-generated portraits still display, otherwise the class illustration. Catalogue (`images:generer`) and scene images (hub/quest) are narrator-side and unaffected.

**Audio (voix).** The table screen reads GM narration via the browser **Web Speech API** (no key) and plays **monster barks** on combat events (`attaque`/`touche`/`rate`/`mort`) broadcast via `BarkDiffuse` on `groupe.{id}`. Bark text lives in `config/barks.php` (voice profile per archetype + `{nom}`-templated boss lines); audio is **pre-generated offline** by `php artisan barks:generer` (and `GenererBarksBoss` per quest) using **Gemini TTS** (`GEMINI_API_KEY`, never called during play). `BanqueBarks` resolves text+url; **without the key or assets, the table speaks the bark text via Web Speech** — audio is pure ambiance, never mechanical. Generated WAVs under `public/audio/barks` are gitignored (regenerable).

⚠ **Every monster has a declared voice — by FAMILY, not by monster** (2026-10-20). `barks.archetypes` mapped only the 8 base monsters, the Champion and the Seigneur: the 63 expansion creatures fell back silently on `defaut`, so the Dragon, the Liche and the Ice Gremlin all said the same « Grrraah ! » in the same voice. Twelve family profiles were added (`ogre`, `ogresse`, `bete`, `sorcier`, `sorciere`, `fleau`, `spectre`, `elfe`, `glace`, `dragon`, `construct`, `tueur`) rather than one per creature: each profile is 12 TTS requests against a 100/day quota, 63 would have been ~756. `BarksArchetypesTest` holds the registry **both ways** — no seeded monster without a voice (ranged variants included), no entry that is not a monster, no profile without lines for every event or without a creature. ⚠ Named boss lines (`lignes_boss`, `GenererBarksBoss`) still exist only for `champion` and `boss`: an expansion boss barks with its family's bank, never its own name — a choice, since every named line is a per-quest TTS request.

**Narrator voice.** Scripted narrator lines live in `config/narration.php` (`lancement` ceremony — broadcast immediately by `DemarreurQuete` when a quest starts — and `repli` variants for every beat — read by `BibliothequeNarration::pourQuete()` whenever the quest's pack lacks a key). `php artisan narration:generer` pre-generates a **dedicated narrator voice** (Gemini, profile `narration.voix`) into `public/audio/narration/{cle}/{i}.wav`; `GenererVoixQuete` does the same, per quest, for the pack's **room descriptions only**, cached by `sha1(texte)` under `public/audio/narration/dyn/`. `NarrationDiffusee` carries an optional `url`; the table plays it, else Web Speech reads the text. ⚠ **A line with variables (`{heros}`, `{or}`, `{monstre}`…) never gets pre-generated audio** (2026-10-20): `narration:generer` used to synthesise all 184 lines, so 73 of them spoke the braces aloud — and `repli()` served that file while the TEXT was substituted, so the table said « {heros} » instead of « Borin ». 73 requests of a 100/day quota for broken audio. `BibliothequeNarration::aDesVariables()` is the single point of passage: the command skips those lines, `repli()` returns `url: null` for them (even if an old file is still on disk), and Web Speech reads the substituted text. ⚠ **A pre-generated file is bound to the TEXT it speaks, not to its rank** (2026-10-20). `{cle}/{i}.wav` used to be linked to its line only by position: editing, adding or reordering a variant left the old file in place, the command skipped it (« already present ») and the table played the OLD sentence over the NEW text — which is why the `reussite_mixte` rewrite needed a manual `rm -r`. Every `{i}.wav` now has an `{i}.sha1` beside it (`App\Partie\Audio\BanqueAudio`, narrator lines **and** archetype barks): at runtime a file is served only if its fingerprint matches the displayed text, else `url: null` and Web Speech; `narration:generer` / `barks:generer` regenerate what changed and **delete** what no longer matches a line (removed rank, line with variables). A file with **no** fingerprint (made before this) is never served — the first run **adopts** it (fingerprint of the current text, zero TTS request): the one bet of the scheme, made once. Boss barks (quest manifest) and `narration/dyn/{sha1}.wav` were already addressed by their text. `BibliothequeNarration` resolves all of this. ⚠ **Gemini TTS quota:** the preview model `gemini-2.5-flash-tts` caps at **100 requests/day even with billing enabled** — generation commands are resumable (skip existing); spread bank generation across days or use Google Cloud TTS for higher limits. Runtime synthesis is gone since 2026-08-18, which is what took a quest from ~38 requests to ~10.

**Background music.** `EtatGroupe::sceneAmbiance()` decides `groupe.ambiance` — **in quest**: `boss` if a revealed living boss/sub-boss is on the board, else `combat` if any revealed living monster, else `exploration`; **at the hub**: `defaite` after a failed last quest, `victoire` after the final boss, else `hub` (`AmbianceSceneTest`). The table (`useAmbiance`) crossfades a random variant listed by `public/audio/ambiance/manifeste.json` (`{scene}/{n}.wav`, fallback flat `{scene}.{ogg|mp3|wav}`) — silent if absent, unlocked by the same gesture as the voice. ⚠ Three front defects fixed 2026-10-21, none of them visible in a test: a scene asked for before the manifest arrived fell back on the flat files (deleted by the script) and stayed **mute** until the next scene change — `ouvrirPiste()` now awaits the manifest; a scene with no track left the **previous** track playing at full volume, out of reach of the mute button; two scene changes during a load (exploration → combat → exploration) left **two** tracks playing together. Every audible track is now held in one set, and any new scene — track or silence — fades out all the others. Loops are **generated by Google's music model Lyria RealTime** (NOT TTS — Gemini TTS can't make music) via `audio-tools/lyria-ambiance.mjs` (Node + `@google/genai`, streams 48 kHz PCM → WAV). See `audio-tools/README.md` for all audio-generation recipes. All `public/audio/**` is gitignored (regenerable).

**Every generated PNG needs its `.webp` twin — run `image-tools/webp.sh` after `images:generer`.** `BibliothequeImages::url()` serves the `.webp` when it exists and falls back to the PNG otherwise, so a missing twin breaks nothing and simply makes the screen **thirty times heavier** — the market went to ~46 MB on a phone before the twins were made (measured 2026-08-22; the mechanism itself dates from René's 2026-08-07 report, "la tablette prend vraiment du temps à charger"). 1024×1024 PNGs weigh ~1.3 MB, their webp ~50 KB. PHP here has **neither gd nor imagick**, so this cannot be an artisan command — it runs in a throwaway container like the audio tools, and ⚠ `apk add` needs root while the files must belong to the host, hence the `su-exec` dance in the script's header (a plain `-u $(id -u)` fails on "Unable to lock database"). The PNG stays the source and is never touched, so `--force` can replay a different quality.

**Le jumeau `.webp` naît AVEC l'image, ce n'est plus une étape**
(`ConvertisseurWebp`, appelé par `BibliothequeImages::enregistrer()`, 2026-09-13).
`image-tools/webp.sh` était un script à relancer *après* coup — donc un geste à
penser, donc un geste oublié : les illustrations des quêtes 98 et 99 sont restées
servies en 1,3 Mo là où 52 et 71 Ko suffisaient. C'est le même défaut de forme que
le ménage des campagnes de harnais : ce qui manquait n'était pas un moyen de
savoir QUOI convertir, c'était le geste lui-même. ⚠ `docker/app/Dockerfile` installe
**GD avec `--with-webp`**, et non un binaire externe : mesuré sur une vraie
illustration, GD et `cwebp` rendent des fichiers **rigoureusement identiques**
(74 706 octets des deux côtés — GD encode avec libwebp, comme cwebp), donc le
sous-processus, le chemin de binaire à sonder et le délai d'attente ne payaient
rien. ⚠ Imagick serait ImageMagick entier plus une compilation PECL pour
convertir un PNG en WebP. ⚠ **Les quatre services `app`/`queue`/`queue-jeu`/
`reverb` ont leur propre image et doivent toutes être reconstruites**, or ce sont
les *queues* qui génèrent les illustrations — reconstruire `app` seul laisse le
défaut entier. ⚠ La conversion reste **best-effort** : sans support WebP, on
garde le PNG et `url()` le sert tel quel — une génération d'image ne doit jamais échouer
parce qu'un outil de compression manque. ⚠ `images:generer` écrivait son PNG avec
un `file_put_contents` à elle : **deux écritures pour une seule règle**, et
celle-là n'en avait pas ; elle passe maintenant par `enregistrer()`.
⚠ **Un test qui écrit dans le vrai `public/` peut le détruire** : la première
version de ces tests a lancé `images:generer --force` sur l'arbre de travail et
écrasé les quatre PNG de portes du catalogue avec 8 octets factices — sans que
rien ne le signale, l'écran restant juste puisque les jumeaux `.webp` intacts
étaient servis. Les PNG ont été reconstruits depuis ces jumeaux (`dwebp`), et les
tests détournent désormais `public_path()` vers un dossier jetable.

**Les alliés ont leur illustration** (René, 2026-10-01 : « il faudrait sûrement des illustrations pour les alliés quand ils font des actions »). Aucun allié n'en avait — ni gabarit, ni génération, ni `image_url` —, et la scène d'attaque d'un allié montrait le **portrait du héros qui le contrôle** sous le nom de l'allié (`acteurHeros($acteur, …, $a['allie'])` : un loup qui mord, avec la tête du barbare). Nouveau type `mercenaires` : gabarit `mercenaire` / `mercenaire_animal` (`config/images.php`), `BibliothequeImages::urlMercenaire()` (emblème `allie` = le buste du camp des héros en repli), itération dans `images:generer --type=mercenaires`, `image_url` publié sur `GET /mercenaires`, `groupe.mercenaires[]` et `entites[]` (le jeton de carte le lisait déjà), et l'action `attaque_allie` porte `mercenaire_id` pour que la scène illustre le bon attaquant. ⚠ **Trois prompts ratés avant le bon**, à ne pas refaire : (1) le seul **type** de catalogue laissait Gemini inventer l'équipement (l'Estafier, « bretteur à deux haches », sortait marteau et bouclier) ; (2) « en pied » et « compagnon d'aventure » faisaient du Croc-sabre — un fauve — un guerrier-tigre debout, d'où un gabarit **à part pour les animaux** ; (3) la description entière mêle allure et **règles** (« sur deux points de vie ») et Gemini les **peignait en chiffres** sur l'armure — le prompt ne garde que l'allure, avant le premier « : » ou « ; ». Le Loup, refusé trois fois (`NO_IMAGE`) avec le premier gabarit, est passé du premier coup avec le gabarit animal.

**Aucun chiffre dans un prompt de meuble ni de carte de Dread** (2026-10-16). Gemini peint ce qu'il lit : « 3 × 2 » a sorti une table étirée à 2,8 : 1 au lieu de 1,5 : 1 (la consigne « occupe presque toute la longueur » l'étirait), et les règles d'une carte se seraient retrouvées peintes sur la carte. L'emprise d'un meuble passe donc en MOTS (`BibliothequeImages::formeMobilier()` : « une fois et demie plus large que haut, son côté le plus long HORIZONTAL »), et la carte de Dread a pour sujet son TYPE d'effet (`images.sorts_dread_effets`), jamais `effet`, qui porte les dés et les crânes. ⚠ Le style à **torches** est écarté des meubles : il a peint un brasero dans la bibliothèque, et une salle à la place d'un meuble. ⚠ **Limite constatée, non résolue** : sur six essais (table, râtelier, armoire, deux chacun), un seul est vu de dessus (l'armoire, premier essai, lue comme une caisse) ; la table reste à 2,8 : 1 pour 1,5 : 1 demandé — la proportion n'est pas contrôlable par le prompt. Un correctif possible serait un paramètre de format de l'API (à vérifier pour ce modèle, non branché) ; il exigerait aussi que le front cesse de cadrer en carré (`object-fit: cover`), sans quoi une image rectangulaire y serait rognée.

**Les meubles ont leur DÉCOUPAGE du livret, vu du dessus** (René, 2026-10-17 : remplacer les illustrations générées, ratées — vue de face, proportions fausses — par les dessins du livret officiel). `public/images/livret/mobiliers/{id}-{slug}.webp` l'emporte dans `BibliothequeImages::urlMobilier()`, puis vient l'image générée, puis l'emblème. ⚠ **Ces dessins sont de l'art Hasbro et le dépôt est PUBLIC : ils ne sont JAMAIS committés** (`.gitignore`, même règle que les PDF des livrets). Ils se découpent à la main sur la machine qui les possède : F2847 p. 17 pour neuf meubles (table, coffre, trône, établi, tombeau, bibliothèque, râtelier, armoire, cheminée) ; F9528 p. 5 (caisse de ravitaillement), G1504 p. 3 (autel, et le coffre au cœur, verso de la même tuile, pour le Coffre du Dread) et F9907 p. 3 (cocon). Le cristal d'Amas et les trois murs n'ont **aucun dessin de dessus** dans les livrets — figurines seulement — et restent sur le généré. Sans les découpages, le jeu retombe sur le généré : un dépôt fraîchement cloné ne casse rien. ⚠ Chaque découpe est **carrée** (dessin centré, reste transparent), parce que `Vignette` rogne en `object-fit: cover` dans un cadre carré (légende 42 px, aperçu de salle 96 px) : une bibliothèque 3 × 1 y serait tronquée.

**Les SYMBOLES de livret — le pictogramme de chaque case, pas une illustration** (chantier symboles, René, 2026-10-24). Ce sont les dessins officiels imprimés sur les livrets de quête, qu'on pose SUR la carte à la place des icônes Material Symbols, dans la silhouette de leur famille (`docs/regles/front-manette-et-table.md`). Ils ne sont PAS générés : aucun `images:generer`, aucun Gemini. Ils vivent **dans le dépôt** — René a levé la règle de l'exclusion le 2026-10-24 : `public/images/livrets/{type}/{slug}.webp`, `{type}` ∈ `mobiliers`, `terrains`, `pieges`, `portes`, `leviers`, `escalier`, `dangers` (`BibliothequeImages::TYPES_SYMBOLE`, fermé). Ne pas confondre avec le dossier **singulier** `public/images/livret/` (découpages des meubles, art Hasbro, toujours hors dépôt par le `.gitignore`) : ce sont deux choses.
- **Le repli reste obligatoire, et c'est `null`, jamais un emblème** : `BibliothequeImages::urlSymboleLivret()` rend `null` sans fichier, `symbole_url` vaut `null`, et le client garde l'icône Material Symbols d'aujourd'hui. Un emblème SVG ici prétendrait « symbole manquant » là où aucun n'était attendu. Le jeu doit rester jouable sans les symboles, comme sans clé d'IA.
- **Le nom du fichier est `Str::slug()` de la clé**, comme pour tout le reste de la bibliothèque : `Forge des nains` → `forge-des-nains.webp` ; le libellé fixe de la porte de pierre `verrou_pierre` se lit donc dans **`portes/verrou-pierre.webp`**. Un fichier au nom littéral (`verrou_pierre.webp`) ne sera jamais servi. Seul le `.webp` est servi : un `.png` seul rend `null`.
- **Les tests n'écrivent JAMAIS dans `public/images/livrets/`** : `SymbolesLivretTest` détourne `public_path()` vers un dossier jetable (`app()->usePublicPath()`), comme `ImagesMobilierLivretTest`. Un faux symbole ne doit pas rester dans le dépôt — même si le dossier est désormais suivi, un test qui le remplit y laisserait un dessin inconnu à committer.
- **Les symboles sont des pictogrammes lus à 22–38 px**, pas des images à agrandir : le client les rend à 80 % de la silhouette, en `object-fit: contain` (un meuble 3 × 1 garde son rapport, jamais rogné). Un dessin mal cadré dans son fichier se lit mal à cette taille : c'est au fichier de cadrer le dessin, le rendu ne rogne rien.
